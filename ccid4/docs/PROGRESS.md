## เฟส 3 — เสร็จ
- `deadlines/rules.py` ฟังก์ชันล้วน (ไม่แตะฐานข้อมูล ไม่อ่านนาฬิกาเอง) + เทสต์ 45 ข้อ ครบทุกช่วงอัตราโทษและกรณีขอบ: ควบคุมตัว 48 ชม. ข้ามเที่ยงคืน, เวลา UTC ↔ ไทย, ฝากขัง 3 ช่วงโทษ (7 / 48 / 84 วัน), ผัดฟ้องศาลแขวง 48 ชม. + 6 วัน × 5, แจ้งความคืบหน้า 30/60 วัน, คดีไม่ปรากฏตัวผู้กระทำผิด 1 ปี, วันหยุดราชการ/เสาร์–อาทิตย์, ผัดทับกัน/ไม่ต่อเนื่อง/เกินวัน/เกินครั้ง
- กติกาเก็บในตาราง `DeadlineRule` (ค่าตั้งต้น + ป้าย "รอฝ่ายกฎหมายตรวจทาน") ผู้ดูแลแก้ที่ `/django-admin/deadlines/deadlinerule/` ทุกการแก้ค่าเก็บเป็นฉบับใหม่ใน `DeadlineRuleVersion` · วันหยุดแก้ที่ `/django-admin/deadlines/holiday/` · `seed_holidays` ใส่วันหยุดที่ตรงวันทุกปี
- แผงขวา 3 ส่วนใช้งานจริง: กำหนดเวลา (สี ปกติ/≤3 วัน/เลยกำหนด, นับถอยหลังสดสำหรับรายชั่วโมง, บอกวันที่ต้องยื่นจริงเมื่อติดวันหยุด) · สิ่งที่ต้องทำ (จากกติกา + เพิ่มเอง) · ทำแล้ว (ติ๊กกลับได้ แสดงเหตุผล/มาตรา และใครทำ)
- งานจากกติกาซิงก์ทุกครั้งที่กดบันทึกคดี: ระบบติ๊กให้เองเมื่อตรวจพบว่าทำแล้ว (เช่น มีคำให้การ) และเปิดกลับถ้าเหตุนั้นหายไป แต่รายการที่คนติ๊กเองระบบไม่แตะ
- ผู้ต้องหาแต่ละคน: การ์ดการควบคุมตัว (กติกาที่ใช้ ใช้ไป เหลือกี่ผัด/กี่วัน วันสุดท้ายถ้าผัดครบ) + กล่อง "บันทึกฝากขังผัดที่ n" ที่เติมวันเริ่มให้และตรวจตามกติกาก่อนบันทึก · ศาลแขวงเปลี่ยนเป็นผัดฟ้องอัตโนมัติ · ประกันตัวแล้วไม่นับ 48 ชม.
- แท็บพนักงานสอบสวน: หนังสือออกภายนอก 4 แบบ (CCTV ธนาคาร โทรศัพท์ แพลตฟอร์ม) ร่าง → ออกเลขอัตโนมัติ → บันทึกวันได้รับตอบ + แนบไฟล์ (PDF/JPG/PNG ≤ 20 MB ดาวน์โหลดผ่านการตรวจสิทธิ์และ audit) · บันทึกพนักงานสอบสวนเป็นเช็กลิสต์เดียวกับแผงขวา ลงอัตโนมัติเมื่อร่าง/ออกหนังสือ ได้รับตอบ บันทึกฝากขัง
- ชิปกำหนดเวลาที่ใกล้ที่สุดที่หัวคดีและในตาราง "คดีของฉัน"
- Timeline คดี (B10) เรียงทุกเหตุการณ์ ส่งออก PDF (LibreOffice ในเครื่อง) หรือ Word และบันทึก audit การส่งออก
- เทสต์รวม 106 ข้อ

### ตัดสินใจระหว่างเฟส
- นับวันฝากขัง/ผัดฟ้องโดยนับวันแรก (ฝาก 12 วันตั้งแต่ 1 ม.ค. ครบ 12 ม.ค.) · กำหนดที่นับเป็นวัน (แจ้งความคืบหน้า, ไม่ปรากฏตัวผู้กระทำผิด) ไม่นับวันแรก · ตั้งค่าได้ในกติกา (`count_first_day`)

- ร่างคำให้การ 3 แบบ: ผู้กล่าวหา, พยาน (มีปุ่ม "ตรวจความสอดคล้อง" ติดธงจุดที่ไม่ตรงกับพฤติการณ์), ผู้ต้องหาตามแนวที่เลือก · ทุกร่างเป็นเวอร์ชันใหม่ที่มีป้าย "ร่างโดย AI – รอตรวจ" จนกว่าพนักงานสอบสวนกด "ยืนยันคำให้การ" (เก็บผู้ยืนยันและเวลา, ผู้ช่วยยืนยันไม่ได้) · ปุ่ม AI ล็อกระหว่างยังไม่บันทึก (A4.1)

- เมนู "รับแจ้งความ & นำเข้าคดี": ลิงก์และ QR ส่วนตัวของพนักงานสอบสวน 2 แบบ (คดีอาญาทั่วไป / คดีอาชญากรรมทางเทคโนโลยี) · คัดลอกลิงก์ · ดาวน์โหลด QR (PNG) · พิมพ์ป้าย A5 พร้อมโลโก้ CCID4 · สร้างลิงก์ใหม่ (ลิงก์เดิมใช้ไม่ได้ทันที) · ปุ่ม "กรอกแทนผู้แจ้ง"
- หน้าสาธารณะ (ไม่ต้องเข้าสู่ระบบ ออกแบบให้ใช้บนมือถือ): เลือกเรื่อง → "คุยกับผู้ช่วย" (ถามทีละเรื่อง 6–7 หัวข้อ: ตัวผู้แจ้ง เหตุการณ์ วันเวลาสถานที่ ความเสียหาย บัญชีที่โอนไป [เฉพาะคดีไซเบอร์] ผู้ต้องสงสัย พยาน) หรือ "กรอกแบบฟอร์ม" ทีละขั้น · แนบไฟล์ภาพ/PDF ได้ 5 ไฟล์ (ตรวจชนิดไฟล์จากเนื้อไฟล์จริง เก็บ SHA-256) · ข้อความยินยอม PDPA ต้องติ๊กก่อนส่ง · ได้เลขอ้างอิงและลิงก์ติดตามสถานะ

- ป้องกันหน้าสาธารณะ: จำกัดข้อความแชท 60 ครั้ง/10 นาที, ส่งเรื่อง 5 ครั้ง/ชั่วโมงต่อ IP, 200 เรื่อง/วันต่อลิงก์, ข้อความยาวไม่เกิน 2,000 ตัวอักษร
- โหมดกรอกแทนผู้แจ้ง: ฟอร์มเดียวกันในระบบภายใน บันทึกว่าเจ้าหน้าที่คนไหนกรอก และใช้ข้อความ "ยินยอมด้วยวาจาต่อหน้าเจ้าหน้าที่" + audit

- `sample_data/mock_arrest_record.pdf` บันทึกจับกุมจำลอง (บุคคลสมมติ) ไว้ทดลองนำเข้า

## เฟส 7 — เสร็จ (หมายเรียกจากทะเบียนคดีของกอง, B1 + SPEC_summons_system.md)
- เมนู "หมายเรียก": ภาพรวม (คดีทั้งหมด / ยังไม่สิ้นสุด / ยังไม่เคยออกหมาย / ที่อยู่ไม่ครบ / รอมาตามนัด / ไม่มาตามนัด + แยกตามพนักงานสอบสวน) · ทะเบียนคดี · นำเข้าข้อมูล · ตั้งค่า
- นำเข้า Excel 2 ไฟล์ (ผู้แจ้ง ชีต Grid / ทะเบียนคดีแยกชีตรายปี) รวมด้วยเลขรับแจ้ง (ตัดช่องว่าง ตัวพิมพ์ใหญ่): อัปโหลด → เลือกชีต → จับคู่คอลัมน์ (อัตโนมัติจากหัวตาราง แก้เองได้และจำไว้ครั้งหน้า) → ตรวจสอบ (ใหม่ / อัปเดต / มีปัญหา / จับคู่อีกไฟล์ไม่ได้ / สถานะเปลี่ยน n คดี) → ยืนยัน · นำเข้าซ้ำ = อัปเดต ไม่สร้างซ้ำ · เบอร์โทรและเลขบัตรเก็บเป็นข้อความ · แถวมีปัญหา (ไม่มีบ้านเลขที่ ไม่มีจังหวัด ไม่มีตำบล/อำเภอ เลขบัตรไม่ครบ 13 หลัก เลขรับแจ้งซ้ำ) นำเข้าได้แต่ติดธง และดาวน์โหลดรายการเป็น Excel · ประวัติการนำเข้าทุกครั้ง
- เติมรหัสไปรษณีย์จาก ตำบล + อำเภอ + จังหวัด (รองรับ ต./ตำบล/แขวง อ./อำเภอ/เขต จ./จังหวัด, กทม.) จากชุดข้อมูลเปิด kongvut/thai-province-data (MIT, ตรวจ license แล้ว) ที่ตัดเก็บไว้ใน `summons/data/` ใช้ในเครื่อง ไม่เรียกเครือข่าย · เก็บแยกจากค่าเดิมในไฟล์
- สถานะในทะเบียนแยกจากสถานะคดี CCID4: ตาราง `RegisterStatus` + ธง "ถือว่าสิ้นสุด" (ค่าตั้งต้น "สิ้นสุด" เท่านั้น) แก้ได้ในตั้งค่า · สถานะใหม่ที่พบตอนนำเข้าสร้างเป็นไม่สิ้นสุดพร้อมป้าย "ใหม่"
- เชื่อมกับคดี CCID4: แถวทะเบียนจับคู่คดีเดิมด้วยเลขรับแจ้ง หรือสร้างคดีสถานะ "นำเข้า" ในบัญชีพนักงานสอบสวนที่ชื่อตรงกัน (ไม่พบ = ผู้นำเข้า, ผูกบัญชีเองได้ในตั้งค่า) พร้อมผู้กล่าวหาจากไฟล์ผู้แจ้ง · ออกหมายแล้วลงบันทึกพนักงานสอบสวน และวันนัดขึ้นในแผง "กำหนดเวลา" ของคดี
- ทะเบียนคดี: ค้นหา กรองสถานะ/ปี/หน่วย/พนักงานสอบสวน/ประเภทคดี ปุ่มลัด "ยังไม่สิ้นสุด" "ยังไม่เคยออกหมาย" "ที่อยู่ไม่ครบ" · ติ๊กหลายแถว → "ออกหมายเรียก (n รายการ)" หรือออกทุกคดีตามตัวกรอง · ส่งออกทะเบียนเป็น Excel คอลัมน์เดิม
- รายละเอียดคดี: ผู้กล่าวหา (เลขบัตรปิดบัง กดดูต้องมีสิทธิ์และ audit) แก้ชื่อ/ที่อยู่ได้ · ประวัติหมาย (ครั้งที่ วันนัด ผู้ลงนาม ไฟล์) บันทึกผล มาตามนัด/ไม่มา/ยกเลิก · ปุ่มออกหมายครั้งถัดไป

4. ติ๊ก "รวมเป็นไฟล์เดียว" และ "พิมพ์ใบจ่าหน้าซอง" → ยืนยัน → ดูแถบความคืบหน้า → ดาวน์โหลด PDF รวมและซอง
5. เปิดคดีหนึ่งในทะเบียน → เห็นประวัติหมายครั้งที่ 1 · กด "เปิดคดีใน CCID4" → แผงกำหนดเวลามี "นัดตามหมายเรียกครั้งที่ 1"

## เฟส 8 — เสร็จ (ห้องสอบปากคำด้วยเสียง, B2 + SPEC_interview_recorder.md) — ความต้องการหลักของผู้ใช้
> ผู้ใช้ย้ำระหว่างเฟส 7: "ความต้องการหลักต้องการสร้างโปรแกรมเพื่อใช้ในการอัดเสียงผู้มาแจ้งความแล้วให้ระบบประมวลผลออกมาเป็นคำให้การออกมาเป็น word"

- **เข้าห้องสอบ:** ปุ่ม "สอบด้วยเสียง" ในแท็บผู้กล่าวหา ผู้ต้องหา พยาน (หรือเมนู "ห้องสอบปากคำ") → ระบุสถานที่และผู้เข้าร่วม (ทนาย ผู้ไว้วางใจ ล่าม+ภาษา ผู้บันทึก) · ผู้ต้องหาต้องผ่านการแจ้งสิทธิ (A4.4) ก่อนจึงเริ่มได้ และแสดงสคริปต์ให้อ่านออกเสียง
- **บันทึกเสียงในเบราว์เซอร์:** ทดสอบไมค์ (แถบระดับเสียง + อัด 5 วินาทีแล้วเล่นกลับ) · ตัวจับเวลา · พัก/ต่อ · ทำเครื่องหมายพร้อมหมายเหตุ · ส่งขึ้นเซิร์ฟเวอร์ทุก 5 วินาที (ส่งซ้ำได้โดยไม่เพิ่มซ้ำ ลองใหม่อัตโนมัติเมื่อเน็ตหลุด) และแสดง "บันทึกขึ้นเซิร์ฟเวอร์แล้วถึงนาทีที่ xx" · ปิดแท็บกลางคันแล้วเปิดใหม่ ท่อนที่ส่งแล้วไม่หาย กด "บันทึกต่อ" ได้ (ทดสอบจริงในเบราว์เซอร์แล้ว)
- **ปิดการบันทึก:** รวมทุกรอบเป็นไฟล์ต้นฉบับ (ไม่เข้ารหัสใหม่) → SHA-256 → ไฟล์เป็นอ่านอย่างเดียวบนดิสก์ → แปลง FLAC 16 kHz mono สำหรับถอดเสียง → เข้าคิวประมวลผล
- **ประมวลผล (แสดงความคืบหน้าทีละขั้น):** ถอดเสียงด้วย Typhoon Whisper ผ่าน faster-whisper (VAD + timestamp และความมั่นใจรายคำ) → แยกผู้พูดด้วย pyannote (ถ้ามีโมเดล) → จับข้อความกับผู้พูด → ตรวจการแจ้งสิทธิ → ร่างถาม–ตอบ → ตรวจต้นทาง · ไม่มีโมเดลในเครื่อง = นำเข้าข้อความถอดเสียง (JSON/SRT/WebVTT/บรรทัดมีเวลา) แทนได้ · โหมดสาธิตมีปุ่มใช้ข้อความถอดเสียงตัวอย่าง
- **หน้าตรวจ:** คลื่นเสียง (wavesurfer) · กดคำหรือป้ายเวลาแล้วเล่นช่วงนั้น ระหว่างเล่นไฮไลต์คำที่กำลังพูด · ไฮไลต์คำความมั่นใจต่ำและตัวเลข · กำหนด "ผู้พูด S1/S2/S3" ว่าเป็นใคร · แก้ข้อความได้ โดยเก็บข้อความต้นฉบับจาก AI และประวัติการแก้ (ใคร เมื่อไร) · ทุกการฟังเสียงลง AuditLog (ไม่มีลิงก์ไฟล์ตรง เล่นผ่านแอปที่รองรับการเลื่อนตำแหน่ง)
- **ร่างถาม–ตอบ:** คำถามจากช่วงที่พนักงานสอบสวนพูด คำตอบจากช่วงที่ผู้ให้การพูด เปลี่ยนสรรพนามเป็น "ข้าฯ" ตัดคำติดปาก/คำลงท้าย ไม่สรุปหรือเติมความ · 2 ระดับ "ใกล้คำพูด" (ค่าตั้งต้น, จับคู่ด้วยโค้ด) และ "ภาษาเขียน" (LLM ในเครื่อง ผ่าน `ai/prompts/arrange_qa.txt`) · ทุกคู่มีช่วงเวลาและ segment ต้นทาง · ร่างใหม่ได้โดยร่างเดิมยังเก็บ
- **ตรวจต้นทางด้วยโค้ด (ไม่ให้ LLM ตรวจตัวเอง):** ตัวเลขทุกตัว เลขบัญชี/เบอร์โทรที่ยาว และทุกวลีของคำตอบต้องพบในเสียงช่วงนั้น (rapidfuzz) ไม่พบ = ธงแดง · ช่วงที่ผู้ให้การพูดแต่ไม่อยู่ในคำตอบใดถูกทำกรอบส้ม · แก้คู่แล้วตรวจใหม่ทันที
- **ตรวจการแจ้งสิทธิจากเสียง:** แจ้งการบันทึกเสียง · แจ้งข้อกล่าวหา (ม.134) · สิทธิให้การหรือไม่ก็ได้ · ถ้อยคำใช้เป็นพยานหลักฐาน · สิทธิมีทนาย/ผู้ไว้วางใจ (ม.134/4) แต่ละข้อบอกเวลาในเสียง กดฟังได้ · ไม่ครบ = ผู้ต้องหาต้องระบุเหตุผลก่อนยืนยัน
- **ยืนยัน:** ต้องติ๊ก "ฟังแล้ว ตรงกับเสียง" ครบทุกคู่ → ล็อกร่าง → **แทนที่คำให้การของบุคคลนั้นในคดี** (ที่มา "จากเสียงสอบปากคำ" พร้อมผู้ยืนยันและเวลา) → ลงบันทึกพนักงานสอบสวน
- **ส่งออก Word/PDF:** หัวเอกสาร · ย่อหน้าแจ้งสิทธิ (ผู้ต้องหา) · ถาม–ตอบพร้อมนาทีในเสียง · บล็อกล่าม · หน้า 2 เป็นต้นไปมีหัว "ใบต่อคำให้การ ของ …" · ช่องลงนาม 5 ฝ่าย · "ได้อ่านให้ฟังแล้ว รับว่าถูกต้อง" · ท้ายกระดาษพิมพ์รหัสเอกสารและ SHA-256 ของไฟล์เสียง · **ชุดหลักฐาน ZIP**: ไฟล์เสียงต้นฉบับ + ข้อความถอดเสียง (JSON, Word, PDF) + คำให้การ + manifest ค่า hash ทุกไฟล์
- แบบฟอร์มชั่วคราว `interviews/library/statement_voice.docx` · เปลี่ยนเป็นแบบฟอร์มจริงได้ในหน้าตั้งค่าโดยอัปโหลดไฟล์ Word (มีตารางรายการตัวแทนที่รองรับ) ไม่ต้องแก้โค้ด · ตั้งค่าสคริปต์แจ้งสิทธิและระยะเก็บไฟล์เสียงได้
- `manage.py eval_asr --audio … --reference … --model … --model …` วัด CER และเวลาประมวลผลต่อนาทีเสียง เทียบ Large v3 กับ Turbo
- Docker: service `worker-gpu` (profile `gpu`, NVIDIA Container Toolkit) ติดตั้ง faster-whisper + pyannote และรับเฉพาะคิว `asr` (ตั้ง `CCID4_ASR_QUEUE=true`) · ไม่มี GPU = worker ปกติรันได้บน CPU (ช้ากว่า ใช้ Turbo)
- fixture จำลอง: การสอบปากคำผู้ต้องหาคดีขายบัญชีม้า 27 ช่วงพูด (มีแจ้งสิทธิครบ เลขบัญชี จำนวนเงิน วันที่ เบอร์โทร) และชุดที่ไม่มีการแจ้งสิทธิ
- เทสต์รวม 205 ข้อ ครบเกณฑ์ตรวจรับของสเปก: ท่อนไม่หายเมื่อปิดแท็บและบันทึกต่อได้ · SHA-256 ตรงกับในเอกสารและไฟล์แก้ไม่ได้ · ทุกคู่มีต้นทาง เลขบัญชีและจำนวนเงินตรงเสียง 100% · แก้ร่างให้มีตัวเลขที่ไม่มีในเสียงแล้วขึ้นธง · ไม่มีการแจ้งสิทธิต้องระบุเหตุผล · Word/PDF ไม่มี `{` หน้าถัดไปมี "ใบต่อคำให้การ" · ทั้งไปป์ไลน์รันได้ขณะบล็อกเครือข่ายภายนอก

### ตัดสินใจระหว่างเฟส
- **ตัวเลขในคำให้การจากเสียงใช้เลขอารบิก** เพื่อให้เลขบัญชี จำนวนเงิน เบอร์โทรตรงกับข้อความถอดเสียงทุกตัวและตรวจย้อนได้ (เอกสารอื่นในระบบยังเป็นเลขไทย) · แจ้งได้ถ้าต้องการเลขไทย
- โหมด "ใกล้คำพูด" จับคู่ด้วยโค้ดแทน LLM (เร็ว ไม่เปลี่ยนถ้อยคำ) · LLM ใช้ในโหมด "ภาษาเขียน" หรือเมื่อเปิด Ollama และตรวจผลด้วยโค้ดเสมอ ถ้า LLM ล้มเหลวกลับไปใช้การจับคู่ตามคำพูด
- ทุกครั้งที่เปิดหน้าบันทึกใหม่ = รอบใหม่ (หัวไฟล์ WebM ของตัวเอง) แล้วรวมตอนปิดด้วย ffmpeg แบบไม่เข้ารหัสใหม่ เพื่อให้ไฟล์ต้นฉบับใกล้ของจริงที่สุด

### ค้าง
- ยังไม่ได้ทดสอบกับ Typhoon Whisper และ pyannote จริง (เครื่องพัฒนาไม่มี GPU) · ต้องเตรียมโมเดลครั้งเดียวบนเครื่อง GPU: แปลง `typhoon-ai/typhoon-whisper-large-v3` เป็น CTranslate2 (`ct2-transformers-converter --model typhoon-ai/typhoon-whisper-large-v3 --output_dir models/typhoon-whisper-large-v3-ct2 --copy_files tokenizer.json preprocessor_config.json --quantization float16`) และวาง pyannote pipeline ไว้ใน `models/pyannote` (ขั้นตอนเต็มเขียนใน OPERATIONS.md เฟส 12)
- ไมค์ใช้ได้เฉพาะ HTTPS: Caddy ออก cert ภายในให้แล้ว แต่ต้องติดตั้ง CA ของ Caddy ในเครื่องผู้ใช้ (ขั้นตอนใน OPERATIONS.md เฟส 12) · การเข้ารหัสดิสก์ (BitLocker/LUKS) และการลบ/ย้ายไฟล์ตามระยะเก็บที่มีผู้อนุมัติ → เฟส 12
- ไฟล์เสียงยังไม่ได้ย้ายเข้าทะเบียนพยานหลักฐาน (B6) → เฟส 10

### วิธีทดสอบด้วยมือ
1. เข้าด้วย `investigator1` เปิดคดี → แท็บผู้กล่าวหา → กด "สอบด้วยเสียง" → ใส่สถานที่ → "ไปหน้าบันทึกเสียง" (ต้องเปิดผ่าน `https://` หรือ `localhost` เบราว์เซอร์จึงให้ใช้ไมค์)
2. กด "ทดสอบไมค์ 5 วินาที" ฟังเสียงตัวเอง → "เริ่มบันทึก" พูดสัก 20 วินาที กด "ทำเครื่องหมาย" → ปิดแท็บทิ้ง แล้วเปิดหน้าเดิมใหม่ ต้องเห็นวินาทีที่บันทึกไว้ → "บันทึกต่อ" อีก 10 วินาที → "หยุด" → "ปิดการบันทึกและประมวลผล"
3. หน้าประมวลผลแสดง SHA-256 และขั้นตอน (เครื่องนี้ไม่มีโมเดลถอดเสียง) → กด "ใช้ข้อความถอดเสียงตัวอย่าง (ข้อมูลจำลอง)" หรือนำเข้าไฟล์ถอดเสียงของหน่วย
4. หน้าตรวจ: กดคำในข้อความถอดเสียง ได้ยินช่วงนั้นและคำถูกไฮไลต์ตามเสียง · ลองแก้คำตอบคู่หนึ่งให้มีตัวเลขที่ไม่มีในเสียง → ขึ้นธงแดง · ติ๊ก "ฟังแล้ว ตรงกับเสียง" ครบทุกคู่
5. กด "ยืนยันและสร้าง Word/PDF" → ดาวน์โหลดคำให้การ Word (หน้า 2 มีหัว "ใบต่อคำให้การ" ท้ายกระดาษมี SHA-256) และชุดหลักฐาน ZIP · กลับไปหน้าคดี คำให้การของบุคคลนั้นเป็นฉบับ "จากเสียงสอบปากคำ"

## ใช้งานจริงกับผู้แจ้งความ (17 พ.ย. 2569, ผู้ใช้ขอหลังเฟส 8)
> ผู้ใช้: "ทำให้สามารถใช้งานจริงเลยครับจะได้ทำการทดสอบกับผู้แจ้งความจริงเลยในวันนี้ให้จับใจความสรุปแก่นความสำคัญเล่าเรื่องออกมาเป็นเรื่องราวแล้วเขียนคำที่พบบ่อยด้วยครับ" และ "ใช้ติดตั้งบนเครื่องผมก่อนเพื่อทดสอบใช้งานจริงการอัดเสียงอาจจะใช้เวลานานด้วยครับ"

- **สรุปจากเสียง (หน้าตรวจ) 3 แท็บ**
  - **สรุปใจความสำคัญ:** เหตุการณ์โดยย่อ · วันเวลา · จำนวนเงิน · เลขบัญชี (ไม่ปนเบอร์โทร) · ธนาคาร · เบอร์โทร · ช่องทาง (เฟซบุ๊ก/ไลน์/…) · ความประสงค์
  - **เล่าเรื่อง:** คำให้การแบบบรรยาย "ข้าฯ ขอให้การว่า …" สร้างจากประโยคของผู้ให้การเรียงตามเวลา
    - เปลี่ยนสรรพนามเป็น ข้าฯ ตัดคำลงท้าย/คำติดปาก และตัดคำตอบสั้น ๆ อย่าง "ใช่/เข้าใจ" ไม่เติมความ
    - แก้ได้ทุกคำ บันทึกแล้วโค้ดตรวจตัวเลขและทุกวลีเทียบกับเสียงใหม่ (ไม่พบ = ป้ายสีส้ม)
    - ต้องติ๊ก "ฟังแล้ว ตรงกับเสียง" ก่อนยืนยัน
  - **คำที่พบบ่อย:** ตัดคำภาษาไทยด้วย PyThaiNLP (newmm, ออฟไลน์) ตัด stopword/คำลงท้าย/สรรพนาม/ตัวเลข/คำวันเดือน · กดคำแล้วไฮไลต์ทุกช่วงในข้อความถอดเสียง
- เมื่อเปิด Ollama ระบบใช้ LLM ในเครื่องเรียบเรียงสรุปและเรื่องเล่า (`ai/prompts/summarize_interview.txt`) และตรวจผลด้วยโค้ดเหมือนเดิม · ไม่มี LLM = ดึงจากคำพูดด้วยโค้ด
- **รูปแบบคำให้การ:** บรรยาย (ค่าตั้งต้นของผู้กล่าวหา/พยาน) หรือ ถาม–ตอบ (ค่าตั้งต้นของผู้ต้องหา) เลือกได้ในหน้าตรวจก่อนยืนยัน
  - แบบบรรยาย: Word ใช้ช่อง `{เรื่องเล่า}` (แยกย่อหน้า) และตัดตารางถาม–ตอบออก
  - แบบฟอร์มที่หน่วยอัปโหลดเองต้องมีช่อง `{เรื่องเล่า}` ถ้าไม่มี ระบบแจ้งชัดเจน
- **สรุปการสอบปากคำ (Word):** ข้อมูลทั่วไป · สรุปใจความ · เรื่องราว · ตารางคำที่พบบ่อย · ข้อสังเกตจากระบบ
  - ดาวน์โหลดได้ตั้งแต่ก่อนยืนยัน ติดป้าย "ร่างโดย AI – รอตรวจ" จนกว่าจะยืนยัน (ลง AuditLog)
  - รวมอยู่ในชุดหลักฐาน ZIP
- **อัดเสียงผู้แจ้งความรายใหม่** (หน้าห้องสอบปากคำ)
  - กรอกชื่อ เบอร์ เรื่องย่อ → สร้างคดีสถานะรับแจ้งใหม่ + ผู้กล่าวหา + ห้องสอบ → ไปหน้าบันทึกเสียงทันที
  - อายุ/ที่อยู่ที่ยังไม่รู้พิมพ์เป็นเส้นจุดให้เขียนด้วยมือ
- **ไม่มีโมเดลแยกผู้พูด:** เดาผู้พูดจากประโยค (คำถาม การแจ้งสิทธิ = พนักงานสอบสวน) · เปลี่ยนผู้พูดรายช่วงได้ในหน้าตรวจ · ไฟล์ถอดเสียงที่ไม่มีป้ายผู้พูดก็ใช้วิธีเดียวกัน
- **อัดเสียงยาวเป็นชั่วโมง**
  - หน้าจอไม่ดับระหว่างอัด (Wake Lock)
  - ส่งท่อนไม่สำเร็จ = ลองใหม่เรื่อย ๆ จนสำเร็จ เสียงไม่หาย (เดิมยอมแพ้หลัง 8 ครั้ง)
  - คงการเข้าสู่ระบบไว้ระหว่างพัก
  - ปิดการบันทึกเร็วขึ้น: ย้ายการแปลง FLAC ไปทำใน worker
  - ความยาวเสียงใช้วินาทีที่นับระหว่างอัด เมื่อ WebM จากเบราว์เซอร์ไม่มีหัวความยาว
  - ถอดเสียงรายงานความคืบหน้า "ถอดเสียงแล้ว mm:ss จาก mm:ss (xx%)"
  - ตั้ง `ASR_BEAM_SIZE`, `ASR_COMPUTE_TYPE`, `ASR_CPU_THREADS` ได้
- **ติดตั้งบนเครื่องเดียว:** `docker-compose.local.yml` · `scripts/install_local.ps1` (Windows) · `scripts/install_local.sh` (macOS/Linux) · คู่มือ `docs/ติดตั้งบนเครื่องเพื่อทดสอบ.md`
  - เปิดที่ `http://localhost:8000` เฉพาะเครื่องนี้ (ไมค์ใช้ได้โดยไม่ต้องมี HTTPS)
  - ถอดเสียงด้วย CPU · worker ทีละรายการ
  - `manage.py setup_asr` โหลดโมเดลครั้งเดียว หรือแปลงโมเดล transformers เช่น Typhoon ด้วย `--convert`
  - `manage.py create_officer` สร้างบัญชีพนักงานสอบสวน
- ทดสอบใน Docker จริงแล้ว: สร้าง image (WITH_ASR) → migrate → สร้างบัญชี → หน้าเว็บ → อัดเสียงด้วยไมค์จำลอง 15 วินาที → ปิด → worker ประมวลผล → นำเข้าข้อความ → 3 แท็บ → บันทึกเรื่องเล่า → ยืนยัน → Word + PDF (LibreOffice) + สรุป Word
  - ข้อจำกัด: เครื่องทดสอบโหลดโมเดลจาก Hugging Face ไม่ได้ (เครือข่ายถูกจำกัด) จึงยังไม่ได้ถอดเสียงด้วยโมเดลจริง

## เฟส 9 — เสร็จ (เส้นทางเงิน/บัญชีม้า B3 · เครือข่ายคดี B4 · กระเป๋าคริปโต B5)
- **แอป `cyber`**: `BankAccount` (ทะเบียนบัญชี: ผู้เสียหาย/ปลายทาง, สถานะ 4 แบบ), `MoneyTransfer`, `OnlineAccount` (LINE ID/โซเชียล/URL/อีเมล), `CryptoWallet`, `CryptoTx`, `Identifier` (ดัชนีข้ามคดี), `MergeProposal` · `core.Notification` (กระดิ่ง)
- **หน้าเส้นทางเงินของคดี** (`/cyber/case/<id>/`, แท็บ "เส้นทางเงิน" ในหน้าคดีออนไลน์)
  - **ธุรกรรม:** เพิ่มเอง · **อ่านจากสลิป** (OCR + LLM ในเครื่อง, `ai/prompts/extract_slip.txt`) กรอกฟอร์มให้พร้อมป้าย "ร่างโดย AI – รอตรวจ" ไม่บันทึกจนกว่าจะกดบันทึก และแนบสลิปเป็นหลักฐาน · **นำเข้า statement** Excel/CSV (UTF-8 หรือ Windows-874) มีหน้าจับคู่คอลัมน์ (ระบบเดาจากหัวตาราง) ดูตัวอย่าง 8 แถว อ่านวันที่ พ.ศ./ค.ศ./เดือนไทย ข้ามรายการเงินเข้าและรายการซ้ำ ไฟล์ชั่วคราวลบทันที
  - **ทะเบียนบัญชีปลายทาง (บัญชีม้า):** ชั้นของบัญชี (ผู้เสียหาย → ชั้น 1 → ชั้น 2 …) ยอดรับ จำนวนครั้ง ช่วงเวลา สถานะ ข้อมูลเจ้าของที่ได้จากธนาคาร · เลขบัญชีปิดบังเป็นค่าเริ่มต้น กดดูเต็มต้องมีสิทธิ์และลง AuditLog
  - **หนังสือถึงธนาคารแบบชุด:** ติ๊กหลายบัญชี เลือก "ขอข้อมูล" หรือ "ขอระงับ + ขอข้อมูล" และช่วงวันที่ → ธนาคารละ 1 ฉบับพร้อมตารางบัญชี (Word + PDF เมื่อมี LibreOffice) ใน ZIP · บันทึกเป็นหนังสือออกภายนอก (A4.6) · บัญชีที่ขอข้อมูลเปลี่ยนสถานะเป็น "ขอข้อมูลแล้ว"
  - **แผนภาพเส้นทางเงิน** (Cytoscape.js self-host) คลิกโหนดดูธุรกรรม ส่งออก PNG · สีมาจาก design token
  - **ผูกกับบัญชีทรัพย์:** ยอดที่ผู้เสียหายโอนออก (ไม่นับเงินที่บัญชีม้าโอนต่อซ้ำ) สร้าง/ปรับแถวในบัญชีทรัพย์ของผู้กล่าวหาอัตโนมัติ (`PropertyItem.auto_source = money`)
- **เครือข่ายคดี (B4)**
  - ดัชนีตัวระบุจากทุกคดี: เลขบัญชี เบอร์โทร (ผู้กล่าวหา/ผู้ต้องหา/พยาน) เลขบัตร LINE ID/โซเชียล URL+โดเมน อีเมล กระเป๋าคริปโต (รวมที่อยู่ในธุรกรรม)
  - normalize ก่อนเทียบ (ตัดขีด/ช่องว่าง เลขไทย→อารบิก +66→0 ตัด @ และ www. hex ไม่สนตัวพิมพ์) · **ดัชนีเก็บเฉพาะ HMAC-SHA256 กับค่าปิดบัง ไม่เก็บเลขจริง** (คีย์จาก `IDENTIFIER_KEY` หรือ `DJANGO_SECRET_KEY`; เปลี่ยนคีย์แล้วรัน `manage.py reindex_identifiers`)
  - ทำดัชนีใหม่อัตโนมัติด้วย signal เมื่อบุคคล/คู่กรณี/บัญชี/บัญชีออนไลน์/กระเป๋า/ธุรกรรมคริปโตเปลี่ยน · เปิดระบบแล้วรัน `reindex_identifiers --missing` ให้คดีเก่า
  - ป้าย **"พบในคดีอื่น n คดี"** ข้างบัญชี บัญชีออนไลน์ กระเป๋า และในแท็บบุคคล (เบอร์โทร/เลขบัตร) · หัวหน้าคดีมีป้าย "เชื่อมโยงกับคดีอื่น n คดี"
  - **แจ้งเตือนเจ้าของคดีทั้งสองฝ่าย** ครั้งเดียวเมื่อพบตัวระบุซ้ำครั้งแรก (บันทึกซ้ำไม่แจ้งซ้ำ)
  - **หน้าเครือข่ายคดี** (`/cyber/network/`): กราฟคดี ↔ ตัวระบุที่พบใน 2 คดีขึ้นไป กรองตามคดี ประเภท ช่วงวันที่รับแจ้ง · ส่งออก PNG และ Excel (ลง AuditLog)
  - **สิทธิ์การดู:** คดีที่ไม่มีสิทธิ์แสดงเป็นกรอบเส้นประ มีแค่เลขคดีกับชื่อพนักงานสอบสวน ไม่มีลิงก์ และไม่แสดงว่าตัวระบุอยู่ตรงไหนในคดีนั้น (เช่น ชื่อบุคคล)
  - **เสนอรวมสำนวน:** ส่งให้หัวหน้างานสอบสวน (แจ้งเตือนในกระดิ่ง) → หัวหน้าเห็นชอบ/ไม่รวม พร้อมความเห็น → แจ้งผู้เสนอและเจ้าของคดีทั้งสอง · ระบบบันทึกการตัดสินใจเท่านั้น ยังไม่ย้ายข้อมูลรวมสำนวนให้อัตโนมัติ
- **กระเป๋าคริปโต (B5)**
  - ตรวจรูปแบบในเครื่อง: BTC (base58check 1…/3… และ bech32/bech32m bc1…) · EVM (0x + 40 hex) · TRON (base58check T…)
  - ธุรกรรมกรอกเองหรือนำเข้า CSV (tx_hash, network, from, to, amount, asset, time)
  - **ส่งออก JSON** ตาม `cyber/schemas/cryptotrace_export.schema.json` (`ccid4.cryptotrace/1`) ตรวจ schema ก่อนส่งออก · **ไม่เรียก blockchain explorer ภายนอก** (มีเทสต์บล็อกเครือข่าย)
- **กระดิ่งแจ้งเตือน** (พื้นฐานของ B8): จำนวนที่ยังไม่อ่าน · รายการ 20 ล่าสุด · กดแล้วอ่านแล้ว (เปิดได้เฉพาะลิงก์ภายในระบบ) · อ่านทั้งหมด
- ข้อมูลจำลอง `manage.py seed_cyber`: 8 คดีออนไลน์ มีบัญชีม้า LINE ID เว็บไซต์ และกระเป๋า TRON ที่ใช้ร่วมกันข้ามคดี · Vercel preview โหลดให้เองถ้ายังไม่มี
- เทสต์รวม 234 ข้อ รวม **เกณฑ์ตรวจรับข้อ 7** (เลขบัญชีเดียวกันใน 2 คดี มีขีด/ไม่มีขีด → ทั้งสองคดีขึ้น "พบในคดีอื่น 1 คดี")
- ทดสอบในเบราว์เซอร์แล้ว (หน้าเส้นทางเงิน 5 แท็บ กราฟ เครือข่ายคดี กระดิ่ง) ไม่มี error ใน console

### ตัดสินใจระหว่างเฟส
- เลขบัญชีในหนังสือถึงธนาคารพิมพ์เต็มและเป็นเลขอารบิก (ธนาคารต้องใช้เลขที่ถูกต้องทุกตัว) · ข้อความอ้างกฎหมายของการขอระงับเขียนแบบไม่ระบุมาตรา ("ตามกฎหมายว่าด้วยมาตรการป้องกันและปราบปรามอาชญากรรมทางเทคโนโลยี") ให้หน่วยแก้ถ้อยคำได้เมื่อมีเครื่องจัดการเทมเพลต (เฟส 10)
- เงินที่ "ไม่ระบุบัญชีต้นทาง" ถือว่ามาจากผู้เสียหาย (ชั้นที่ 1)
- ตัวระบุที่สั้นเกินไป (เลขบัญชี < 6 หลัก, เบอร์ที่ไม่ใช่ 9–10 หลัก) ไม่นำไปเชื่อมคดี เพื่อไม่ให้จับคู่ผิด
- เลขบัญชีและเลขบัตรในตาราง `Person`/`BankAccount` ยังเก็บแบบข้อความ (แสดงแบบปิดบัง) · การเข้ารหัสระดับฟิลด์ตามสเปกข้อ 6 ทำในเฟส 12 (ดัชนีข้ามคดีเป็น HMAC แล้ว)

### วิธีทดสอบด้วยมือ
1. เปิดคดี → แท็บ "พยานหลักฐาน/ของกลาง" → "เปิดหน้าพยานหลักฐาน" → อัปโหลดภาพและ PDF พร้อม "ได้มาจาก" → กดการ์ดไฟล์ ต้องเปิดดูได้ในหน้าและเห็น SHA-256 → "ตรวจความครบถ้วน" ต้องขึ้น "ตรงกับตอนรับเข้า"
2. ดาวน์โหลดโดยเว้นเหตุผลว่าง → ระบบไม่ยอม · ใส่เหตุผลแล้วดาวน์โหลด → ดูแท็บ "บันทึกการครอบครอง" ต้องเห็นชื่อคุณ เวลา และเหตุผล
3. แท็บ "ทะเบียนของกลาง" → เพิ่มโทรศัพท์ (ติ๊ก "ดิจิทัล") → "ส่งมอบ" ให้ พฐ. พร้อมเหตุผล → "รับคืน" → หน้าออกเอกสาร ออก "บัญชีของกลาง" และ "บันทึกตรวจยึดพยานหลักฐานดิจิทัล"
4. เข้าด้วยหัวหน้า (`supervisor1`) → เมนู "เทมเพลตเอกสาร" → เลือก "บันทึกถอนคำร้องทุกข์" → ดาวน์โหลดไฟล์มาตรฐาน แก้ถ้อยคำใน Word แล้วอัปโหลด → จับคู่ → เปิดใช้ → ออกเอกสารนี้ในคดี ต้องได้ถ้อยคำใหม่ · ประวัติเอกสารระบุเวอร์ชัน
5. หน้าออกเอกสาร → "รวมสำนวนเป็น PDF เล่มเดียว" → สลับลำดับ → รวม → ดาวน์โหลด ต้องมีหน้าสารบัญ เลขหน้า "หน้า n / N" และชื่อผู้ส่งออกทุกหน้า

### ตัดสินใจระหว่างเฟส
- **"คดีค้างนาน"** = ไม่มีการแก้ไขเกิน 30 วัน
- **ตัวเลขฐานความผิด** นับเฉพาะเดือนที่เลือก (ถ้าเดือนนั้นไม่มีคดี นับทั้งหมด)
- **ความเสียหาย** ใช้ค่าที่มากกว่าระหว่าง "มูลค่าความเสียหาย" ในข้อมูลคดี กับผลรวมบัญชีทรัพย์ (ซึ่งรวมยอดจากเส้นทางเงินแล้ว)
- **ผู้ดูแลระบบ** เห็นแดชบอร์ดหน่วยงานแบบตัวเลขรวมได้ แต่ยังเปิดเนื้อหาคดีไม่ได้
- **รูปจากบัตร** แสดงในหน้าตรวจทานเท่านั้น ไม่บันทึกลงระบบ
- **ลิงก์ติดตามอยู่นอกเครือข่ายหน่วยไม่ได้:** ผู้แจ้งเปิดลิงก์จากนอกหน่วยได้เมื่อหน่วยแยกหน้าสาธารณะไว้ใน DMZ แล้ว (`CCID4_PUBLIC_URL`) ตามข้อ 11 ของคู่มือ

### ค้าง
- **ยังไม่ได้ทดสอบกับเครื่องอ่านบัตรจริง** (เครื่องพัฒนาไม่มีฮาร์ดแวร์) ทดสอบด้วยเครื่องอ่านจำลองและข้อมูลรูปแบบบัตรจริง
  - ถ้าเครื่องอ่านบางรุ่นต้องใช้คำสั่ง GET RESPONSE ต่างไป ให้ส่งข้อความ error ที่ card-agent แสดงมา
- **ยังไม่ได้ทดสอบการส่งอีเมลกับ SMTP ของหน่วยจริง** ทดสอบด้วย mail backend ของ Django

### วิธีทดสอบด้วยมือ
1. **ภาพรวม:** เข้าด้วย `investigator1` → ดูการ์ด 4 ใบ และรายการเลยกำหนดที่คลิกเปิดคดีได้ → ใส่อีเมลแล้วติ๊ก "รับสรุปรายวัน"
2. **แดชบอร์ดหน่วยงาน:** เข้าด้วย `supervisor1` → เมนูแดชบอร์ดหน่วยงาน → ชี้แท่งกราฟดูจำนวน → เปลี่ยนเดือน → "รายงาน Excel" และ "รายงาน PDF"
3. **โอนคดีและกระดิ่ง:**
   1. `supervisor1` เปิดคดีหนึ่ง → "โอนคดี" ให้ `investigator2` พร้อมเหตุผล
   2. เข้าด้วย `investigator2` → กระดิ่งต้องมี "รับโอนคดี"
4. **ลิงก์ติดตามของผู้แจ้ง:**
   1. หน้าคดี เลื่อนลงไปที่ "หน้าติดตามสถานะสำหรับผู้แจ้ง" → สร้างลิงก์ 30 วัน → เผยแพร่ข้อความ
   2. เปิดลิงก์ในหน้าต่างไม่ระบุตัวตน ต้องเห็นข้อความนั้น แต่ไม่เห็นชื่อหรือข้อมูลอื่นของคดี
   3. กดยกเลิกลิงก์ → เปิดลิงก์เดิมต้องขึ้น "หมดอายุหรือถูกยกเลิก"
5. **อ่านบัตรประชาชน:**
   1. ติดตั้ง card-agent ตาม `card_agent/README.md` บนเครื่องที่มีเครื่องอ่านบัตร
   2. หน้าคดี → แท็บผู้กล่าวหา → "อ่านบัตรประชาชน" → ตรวจทาน → "ใช้ข้อมูลที่เลือก" → "บันทึก"
   3. หัวหน้าเปิด `/audit/` ต้องเห็น "เติมข้อมูลบุคคลจากบัตรประชาชน"

## แก้ไขหลังเฟส 11 — สร้างบัญชีภาษาไทยผ่านหน้าต่างคำสั่ง
- **อาการ:** ตัวติดตั้งบน Windows ขึ้น `Traceback` (`UnicodeEncodeError ... surrogates not allowed`) ตอนสร้างบัญชีคนแรก แล้วเข้าสู่ระบบไม่ได้ ("ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง")
- **สาเหตุ:** บัญชีไม่ได้ถูกสร้าง ข้อความภาษาไทยที่พิมพ์ผ่าน `docker exec` มาถึงไม่ครบ PostgreSQL จึงปฏิเสธตอนบันทึก
  - **กด Backspace ลบอักษรไทย** (พบจริง): เทอร์มินัลในคอนเทนเนอร์ไม่ได้เปิดโหมด UTF-8 (`IUTF8`) จึงลบแค่ 1 ใน 3 ไบต์ของอักษรไทย บนจอดูถูกต้องแต่มีเศษไบต์ค้าง
  - คอนโซลที่ส่งตัวอักษรเป็น code page 874 แทน UTF-8 (กันไว้ด้วย)
- **แก้:**
  - `create_officer` เปิด `IUTF8` ก่อนถาม (Backspace ลบทีละตัวอักษร) แล้วคืนค่าเดิมเมื่อเสร็จ
  - ถ้ายังมีเศษไบต์ค้างก็ตัดทิ้ง ได้ข้อความตามที่เห็นบนจอ ถ้าเป็นรหัส 874 ก็แปลงกลับ ถ้ายังอ่านไม่ได้ก็ถามใหม่ ไม่ล้ม
  - ชื่อผู้ใช้และรหัสผ่านต้องเป็นแป้นภาษาอังกฤษ บอกแยกว่าสั้นเกินไปหรือพิมพ์สองครั้งไม่ตรงกัน
  - ยกเลิกด้วย Ctrl+C ไม่ค้างครึ่งทาง และถ้าบันทึกไม่ได้ก็แจ้งเป็นข้อความไทยแทน Traceback
  - `install_local.ps1` ถามชื่อด้วย PowerShell (`Read-Host`) แล้วส่งเป็นตัวเลือกบรรทัดคำสั่ง ในคอนเทนเนอร์จึงพิมพ์แค่รหัสผ่าน
- **แก้ซ้ำ:** รุ่นแรกของการแก้ล้มในคอนเทนเนอร์ด้วย `AttributeError: termios.IUTF8` เพราะ Python 3.12 (ใน Docker image) ไม่มีค่าคงที่นี้ (มีตั้งแต่ 3.13 ซึ่งเครื่องพัฒนาใช้)
  - ใช้ค่า `0o40000` ของ Linux แทน และการเปิด IUTF8 ทำไม่ได้ก็ข้ามไป ไม่ทำให้การสร้างบัญชีล้ม
  - ทดสอบคำสั่งนี้ด้วย Python 3.12 เพิ่มด้วย
- **ตัดสินใจ:** ไม่เปลี่ยน code page ของคอนโซลเป็น 65001 เพราะคอนโซล Windows บางรุ่นอ่านภาษาไทยใน UTF-8 เป็นค่าว่าง
