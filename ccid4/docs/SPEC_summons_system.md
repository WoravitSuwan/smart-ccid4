# สเปกสำหรับ Claude Code: ระบบออกหมายเรียกผู้กล่าวหา (บก.สอท.4)

## บทบาทและวิธีทำงาน
คุณคือนักพัฒนาที่จะสร้างเว็บแอปภายในหน่วยงานตำรวจตามสเปกนี้
- อ่านสเปกทั้งหมดและดูไฟล์ใน `sample_data/` กับ `templates_docx/` ก่อน แล้วสรุปแผนงานให้ผมอนุมัติก่อนเริ่มเขียนโค้ด
- ทำทีละเฟส (ดูหัวข้อ "เฟสการพัฒนา") จบแต่ละเฟสให้รันเทสต์ บอกวิธีลองใช้ แล้วรอผมยืนยันก่อนไปเฟสถัดไป
- ถ้าโครงสร้างไฟล์ตัวอย่างหรือแบบฟอร์มไม่ตรงกับที่เขียนไว้ ให้ถามผมก่อน ห้ามเดา
- หน้าจอและข้อความที่ผู้ใช้เห็นเป็นภาษาไทย ส่วนโค้ด ชื่อตัวแปร และคอมเมนต์เป็นภาษาอังกฤษ

## เป้าหมายของระบบ
1. นำเข้าข้อมูลคดีทั้งหมดของกองจากไฟล์ Excel 2 ไฟล์ แล้วรวมกันด้วย "เลขรับแจ้ง"
2. คัดคดีที่สถานะยังไม่สิ้นสุด
3. ออกหมายเรียกผู้กล่าวหาได้ทีละคนหรือหลายคนพร้อมกัน จากแบบฟอร์ม Word ที่หน่วยงานใช้อยู่
4. ส่งออกหมายเรียกและใบจ่าหน้าซองเป็น Word (.docx) และ PDF
5. ข้อมูลทั้งหมดนำเข้าซ้ำได้ (อัปเดตของเดิม ไม่สร้างซ้ำ)

ผู้ใช้: ผู้ดูแลระบบ, หัวหน้า, พนักงานสอบสวน, เจ้าหน้าที่ธุรการ

## เทคโนโลยี
- Python 3.12, Django 5, PostgreSQL 16
- หน้าเว็บ: Django templates + HTMX + Tailwind CSS (ไม่ต้องแยก frontend)
- อ่าน Excel: pandas + openpyxl
- สร้าง Word: python-docx (เขียนตัวแทนที่ข้อความเองตามหัวข้อ "แบบฟอร์ม Word")
- รวม Word หลายไฟล์: docxcompose
- แปลง Word เป็น PDF: LibreOffice headless (`soffice --headless --convert-to pdf`) เพื่อให้ PDF หน้าตาตรงกับ Word
- งานเบื้องหลัง (นำเข้าไฟล์ใหญ่, ส่งออกหลายร้อยฉบับ): Celery + Redis
- ติดตั้งด้วย Docker Compose (web, worker, db, redis) บนเครื่องภายในหน่วยงาน อาจเป็น Windows ที่ใช้ Docker Desktop
- ฟอนต์: ติดตั้ง TH SarabunIT๙ และ TH Sarabun New ใน Docker image จากโฟลเดอร์ `fonts/` (ผมจะนำไฟล์ฟอนต์มาใส่เอง) ถ้าไม่มีฟอนต์นี้ PDF จะเพี้ยน
- เทสต์: pytest + pytest-django

## ข้อมูลนำเข้า

### ไฟล์ที่ 1: ข้อมูลผู้แจ้ง (ส่งออกจากระบบรับแจ้งความออนไลน์)
- ชีตเดียวชื่อ `Grid` หัวตารางแถวที่ 1
- คอลัมน์: เลขรับแจ้ง, คำนำหน้าชื่อ, ชื่อ, นามสกุล, อายุ, เลขประจำตัวประชาชน, หมายเลขโทรศัพท์, บ้านเลขที่, หมู่, อาคาร/ตึก, ซอย, ถนน, ตำบล, อำเภอ, จังหวัด, รหัสไปรษณีย์, ที่อยู่อาศัย, สถานภาพ, ระดับการศึกษา, บุคคลที่สาม, อาชีพ, สถานที่ทำงาน, รายได้, ชื่อบิดา, ชื่อมารดา, จังหวัดที่อยู่ขณะที่แจ้ง, สะดวกที่หน่วยใด, ประเภทคดี
- ไฟล์จริงมีประมาณ 18,000 แถว คอลัมน์ ที่อยู่อาศัย ถึง จังหวัดที่อยู่ขณะที่แจ้ง มักว่างทั้งคอลัมน์
- ลักษณะข้อมูลจริงที่ต้องรับมือ:
  - เลขรับแจ้ง = ตัวอักษร 1 ตัว (L, W, T, C) ตามด้วยตัวเลข 9–11 หลัก
  - คำนำหน้าชื่อมีแค่ประมาณ 30% ของแถว
  - เลขประจำตัวประชาชนมีแค่ประมาณ 25% ของแถว
  - รหัสไปรษณีย์แทบไม่มี (ต่ำกว่า 5%)
  - บางแถวไม่มีบ้านเลขที่ หรือไม่มีตำบล/อำเภอ/จังหวัด
  - ข้อความมีช่องว่างท้ายเยอะ (โดยเฉพาะประเภทคดี)
  - เบอร์โทรและเลขบัตรต้องเก็บเป็นข้อความ ห้ามแปลงเป็นตัวเลข (เลข 0 นำหน้าจะหาย)

### ไฟล์ที่ 2: ทะเบียนคดีของกอง
- หลายชีต แยกรายปี ชื่อชีตแบบ `ปี 2569 (2026)` ให้ผู้ใช้เลือกได้ว่าจะนำเข้าชีตไหน
- คอลัมน์: ลำดับ, เลขรับแจ้ง, เลขคดีอาญา, วันที่รับแจ้ง, เดือนที่รับแจ้ง, ปีที่รับแจ้ง, ผู้เสียหาย, เพศ, อายุ, ประเภทคดี, ประเภทคดีระดับ 1, ประเภทคดีระดับ 2, ประเภทคดีระดับ 3, ประเภทกลุ่มคดี, รายละเอียด, มูลค่าความเสียหาย, บช., บก./ภ.จว., หน่วยที่รับผิดชอบ, พนักงานสอบสวน, พนักงานสืบสวน, สถานะ, เบอร์โทรศัพท์ผู้เสียหาย, เลขอ้างอิงธนาคาร, บันทึกการติดต่อ, ประจำวัน, หมายเหตุ
- ลักษณะข้อมูลจริงที่ต้องรับมือ:
  - ชีตมีแถวว่างต่อท้ายจำนวนมาก ให้ข้ามแถวที่ไม่มีเลขรับแจ้ง
  - วันที่รับแจ้งแยกเป็น 3 คอลัมน์ วัน/เดือน/ปี โดยปีเป็น **ค.ศ.** ให้รวมเป็นวันที่เดียว
  - บันทึกการติดต่อและประจำวัน เป็นข้อความรูปแบบ `dd/mm/yyyy HH:MM` (ค.ศ.)
  - เลขคดีอาญามีเฉพาะบางคดี รูปแบบ `259/2569`
  - ผู้เสียหายเป็นชื่อ-นามสกุลรวมในช่องเดียว
  - หน่วยที่รับผิดชอบมี `กก.1 บก.สอท.4` และ `กก.2 บก.สอท.4`
  - ค่าสถานะที่พบ: สิ้นสุด, อายัดบัญชี, พบพนักงานสอบสวน, ออกหมายเรียก, ส่งสำนวนอัยการ, ระหว่างดำเนินการ, จับกุม, ออกหมายจับ

### กติกาการนำเข้า
- คีย์หลักคือเลขรับแจ้ง: ตัดช่องว่างและแปลงเป็นตัวพิมพ์ใหญ่ก่อนเทียบ
- นำเข้าซ้ำ = อัปเดตแถวเดิม (upsert) และสรุปว่าอะไรเปลี่ยน เช่น "สถานะเปลี่ยน 12 คดี"
- ตัดช่องว่างหัวท้ายทุกช่องข้อความ
- จับคู่คอลัมน์อัตโนมัติจากชื่อหัวตารางข้างบน ถ้าหัวตารางไม่ตรงให้ผู้ใช้จับคู่เอง และบันทึกการจับคู่ไว้ใช้ครั้งหน้า
- ก่อนบันทึกจริง ให้แสดงหน้าตรวจสอบ: เพิ่มใหม่ X / อัปเดต Y / มีปัญหา Z / จับคู่กับอีกไฟล์ไม่ได้ W
- แถวที่มีปัญหา (ไม่มีบ้านเลขที่, ไม่มีจังหวัด, เลขรับแจ้งซ้ำในไฟล์, เลขบัตรไม่ใช่ 13 หลัก) ยังนำเข้าได้ แต่ติดธงไว้ และดาวน์โหลดรายการปัญหาเป็น Excel ได้
- เติมรหัสไปรษณีย์อัตโนมัติจาก ตำบล + อำเภอ + จังหวัด โดยใช้ชุดข้อมูลเปิดของไทย (เช่น kongvut/thai-province-data บน GitHub ตรวจ license ก่อน) ต้องรองรับชื่อที่มีคำนำหน้า เช่น "ต.", "ตำบล", "อ.", "อำเภอ", "จ."
- เก็บประวัติการนำเข้าทุกครั้ง: ไฟล์, ชีต, ผู้นำเข้า, เวลา, จำนวนแต่ละประเภท

## สถานะคดี
- ตาราง Status เก็บชื่อสถานะ + ธง `is_final`
- ค่าเริ่มต้น: "สิ้นสุด" เป็น final เพียงสถานะเดียว ที่เหลือถือว่ายังไม่สิ้นสุด
- ผู้ดูแลระบบแก้ได้ในหน้าตั้งค่า (เช่น อาจตั้งให้ "ส่งสำนวนอัยการ" นับว่าสิ้นสุดด้วย)
- สถานะใหม่ที่เจอตอนนำเข้า ให้สร้างอัตโนมัติเป็นไม่ final และแจ้งเตือนผู้ดูแล

## โมเดลข้อมูล (ปรับได้ แต่ต้องครอบคลุม)
- Complainant: เลขรับแจ้ง (unique) และทุกคอลัมน์จากไฟล์ที่ 1, ธงที่อยู่ไม่ครบ, รหัสไปรษณีย์ที่ระบบเติม (แยกจากค่าเดิม)
- Case: เลขรับแจ้ง (unique, เชื่อม Complainant) และทุกคอลัมน์จากไฟล์ที่ 2, วันที่รับแจ้ง (date), มูลค่า (Decimal), FK ไป Status, Investigator, Unit, ชีตต้นทาง
- Investigator: ชื่อตามที่ปรากฏในทะเบียน (ใช้จับคู่), ยศ (เต็ม เช่น พันตำรวจโท), ชื่อ-สกุลที่ใช้ลงนาม, ตำแหน่ง, โทรศัพท์, หน่วย
- Unit: ชื่อหน่วย, ข้อความสถานที่นัด ("ไป ณ ที่ ..."), ที่อยู่ผู้ส่งสำหรับซอง
- Summons: คดี, ครั้งที่, วันออกหมาย, วันเวลานัด, สถานที่, เหตุที่เรียก, ผู้ออกหมาย, เวอร์ชันแบบฟอร์ม, ไฟล์ docx/pdf, ผล (ออกแล้ว/มาตามนัด/ไม่มา/ยกเลิก), ผู้สร้าง
- DocTemplate: ประเภท (หมายเรียก/ซอง), ไฟล์, เวอร์ชัน, ใช้งานอยู่หรือไม่
- ImportBatch, ImportIssue, AuditLog

## หน้าจอ
(ถ้าผมส่งไฟล์ออกแบบจาก Claude Design มาให้ ให้ทำตามนั้น)
1. **หน้าหลัก:** ตัวเลขคดีทั้งหมด / ยังไม่สิ้นสุด / ยังไม่เคยออกหมาย / ที่อยู่ไม่ครบ / รอมาตามนัด / ไม่มาตามนัด และสรุปแยกตามพนักงานสอบสวน
2. **นำเข้าข้อมูล:** wizard อัปโหลด → เลือกชีต → จับคู่คอลัมน์ → ตรวจสอบ → ยืนยัน, และประวัติการนำเข้า
3. **ทะเบียนคดี:** ตารางแบ่งหน้า ค้นหา กรองตามสถานะ/ปี/หน่วย/พนักงานสอบสวน/ประเภทคดี, ปุ่มลัด "ยังไม่สิ้นสุด" และ "ที่อยู่ไม่ครบ", เลือกหลายแถวแล้วกด "ออกหมายเรียก (n รายการ)", ส่งออกทะเบียนกลับเป็น Excel คอลัมน์เดิม
4. **รายละเอียดคดี:** ข้อมูลผู้กล่าวหา (เลขบัตรปิดบางส่วน), แก้ไขที่อยู่ได้, ข้อมูลคดี, ประวัติหมายเรียก, ปุ่มออกหมายครั้งถัดไป
5. **ออกหมายเรียก:**
   - จัดกลุ่มรายชื่อตามพนักงานสอบสวน เพราะผู้ลงนามต่างกัน
   - วันนัดเริ่มต้น = วันออกหมาย + 14 วัน เวลา 09.00 น. (ถ้าตรงเสาร์อาทิตย์ให้เลื่อนเป็นวันจันทร์ และเลือกไล่เวลาทีละ 30 นาทีได้)
   - สถานที่นัดตามหน่วยที่รับผิดชอบ, เหตุที่เรียกค่าเริ่มต้น "มาให้การต่อพนักงานสอบสวนตามประเด็นที่เกี่ยวข้องกับคดี"
   - ตัวอย่างหมายแบบ PDF ก่อนยืนยัน
   - ตรวจข้อความที่ต้องมีตาม ป.วิ.อ. มาตรา 53 ให้ครบ: สถานที่ออกหมาย, วันที่ออกหมาย, ชื่อและที่อยู่ผู้ถูกเรียก, เหตุที่เรียก, สถานที่และวันเวลาที่ให้มา, ลายมือชื่อและตำแหน่งผู้ออกหมาย ถ้าไม่ครบห้ามออก
   - มีตัวเลือก "เปลี่ยนสถานะคดีเป็น 'ออกหมายเรียก'" (ค่าเริ่มต้น: ไม่ติ๊ก)
6. **ส่งออก:** PDF / Word / ทั้งสองแบบ, รวมเป็นไฟล์เดียว หรือแยกรายคนใส่ ZIP, พิมพ์ใบจ่าหน้าซองพร้อมกัน, แสดงความคืบหน้า
7. **ตั้งค่า:** พนักงานสอบสวน, หน่วย, สถานะ, แบบฟอร์ม (อัปโหลดและแสดงรายการช่องที่ใช้ได้), ผู้ใช้และสิทธิ์

## แบบฟอร์ม Word

### แบบฟอร์มหมายเรียก (`summons_template_sanitized.docx`)
- ชื่อเอกสาร "หมายเรียกผู้กล่าวหา/พยานบุคคล" มีตราครุฑ กล่องคำเตือน ตารางจัดหน้า และส่วน "ใบรับหมายตำรวจ" ด้านล่าง
- ฟอนต์ TH SarabunIT๙ ตัวเลขในเอกสารเป็นเลขไทย
- ใช้ตัวแทนแบบปีกกาเดียวภาษาไทยที่เจ้าหน้าที่ใช้อยู่แล้ว ต้องรองรับรูปแบบนี้:

| ตัวแทนในแบบฟอร์ม | ค่าที่ใส่ |
|---|---|
| `{วันปัจจุบัน}` | วันที่ออกหมาย เลขไทย เช่น ๙ |
| `{เดือนปัจจุบัน}` | ชื่อเดือนไทยเต็ม เช่น กุมภาพันธ์ |
| `{ปีปัจจุบัน}` | **2 หลักท้ายของ พ.ศ.** เช่น ๖๙ (เพราะแบบฟอร์มพิมพ์ "พ.ศ. ๒๕" ไว้แล้ว) |
| `{ชื่อผู้แจ้ง}` | คำนำหน้า + ชื่อ + นามสกุล (ไม่มีคำนำหน้าก็ไม่ใส่ ห้ามเดา) |
| `{ที่อยู่}` | บ้านเลขที่ หมู่ อาคาร ซอย ถนน ตำบล อำเภอ จังหวัด รหัสไปรษณีย์ (ข้ามช่องที่ว่าง) |
| `{ยศผู้ออกหมาย}` `{ชื่อผู้ออกหมาย}` `{ตำแหน่งผู้ออกหมาย}` `{โทรศัพท์ผู้ออกหมาย}` | จากข้อมูลพนักงานสอบสวนของคดี |
| `+14` | ในช่อง "ในวันที่" ของวันนัด: แทนด้วยวันนัด |

- ช่อง "เดือน" และ "พ.ศ. ๒๕" ของวันนัดในแบบฟอร์มเดิมว่างอยู่ ให้สร้างแบบฟอร์มเวอร์ชันใหม่ที่เพิ่ม `{วันนัด}` `{เดือนนัด}` `{ปีนัด}` (ปี 2 หลัก) แทน `+14` และช่องว่างเหล่านั้น โดยไม่แตะไฟล์ต้นฉบับ แล้วรองรับทั้งสองเวอร์ชัน
- ข้อความใน Word มักถูกแบ่งเป็นหลาย run ตัวแทนอาจถูกแบ่งกลางคำ ต้องรวม run ก่อนแทนที่ และรักษาฟอร์แมตของ run แรกไว้
- ต้องแทนที่ทุกตำแหน่ง: ย่อหน้าปกติ ตาราง ตารางซ้อน กล่องข้อความ (w:txbxContent) และ header/footer
- มีตัวเลือก "แปลงตัวเลขในข้อมูลเป็นเลขไทย" (ค่าเริ่มต้น: เปิด)
- ตัวแทนที่ไม่รู้จักหรือไม่มีค่า ให้แจ้งเตือนก่อนออกหมาย ห้ามปล่อยให้ `{...}` หลุดไปในเอกสาร

### ใบจ่าหน้าซอง
แบบฟอร์มเดิมมีข้อมูลจริงอยู่ ให้สร้างแบบฟอร์มใหม่ขนาดซอง DL (หรือพิมพ์ลง A4) ที่มี
- มุมซ้ายบน: ชื่อหน่วยและที่อยู่ผู้ส่ง (จาก Unit)
- ด้านขวา: "กรุณาส่ง" ชื่อผู้รับ ที่อยู่ และรหัสไปรษณีย์ตัวใหญ่
- ใช้ตัวแทนแบบเดียวกับหมายเรียก

### การส่งออก
- 1 คน = docx 1 ไฟล์ ตั้งชื่อ `{เลขรับแจ้ง}_{ชื่อ}_หมายเรียกครั้งที่{n}.docx` (ZIP รองรับชื่อไทยแบบ UTF-8)
- "รวมไฟล์เดียว": รวม docx ด้วย docxcompose (ขึ้นหน้าใหม่ทุกคน) แล้วแปลงเป็น PDF ครั้งเดียว จะเร็วกว่าแปลงทีละไฟล์
- ส่งออกเกิน 20 ฉบับให้ทำใน Celery และแสดงความคืบหน้า

## ความปลอดภัยและ PDPA
- ต้องล็อกอินทุกหน้า สิทธิ์ตามบทบาท:
  - ผู้ดูแลระบบ: ทุกอย่าง
  - หัวหน้า: ดูทั้งหมด ออกหมาย ส่งออก
  - พนักงานสอบสวน: ดูทั้งหมด ออกหมายในคดีของตัวเอง
  - ธุรการ: นำเข้า ออกหมาย ส่งออก
- เลขบัตรประชาชนแสดงแบบปิดบางส่วน (x-xxxx-xxxxx-12-3) ยกเว้นผู้มีสิทธิ์กดดู และบันทึกทุกครั้งที่กดดู
- AuditLog บันทึก: นำเข้า, ออกหมาย, ส่งออก, ดาวน์โหลด, ดูเลขบัตร, แก้ไขข้อมูล

- ไฟล์ที่ส่งออกเก็บใน `media/` และลบอัตโนมัติหลัง N วัน (ตั้งค่าได้)

## เฟสการพัฒนา
1. โครงโปรเจกต์, Docker Compose, โมเดล, ล็อกอิน, `thai_format.py` + เทสต์
2. นำเข้าข้อมูลทั้งสองไฟล์ + หน้าตรวจสอบ + ประวัติ + เติมรหัสไปรษณีย์
3. ทะเบียนคดี + ตัวกรอง + รายละเอียดคดี + แก้ที่อยู่ + ส่งออกทะเบียนเป็น Excel
4. ตัวแทนที่ข้อความใน Word (รองรับ run แตก, ตาราง, กล่องข้อความ) + ออกหมายเรียก + ตัวอย่าง PDF
5. ส่งออกแบบหลายฉบับ, รวมไฟล์, ZIP, ใบจ่าหน้าซอง, Celery
6. ตั้งค่า, สิทธิ์, AuditLog, README ภาษาไทย (วิธีติดตั้งบน Windows + Docker Desktop, วิธีใส่ฟอนต์, วิธีสำรองฐานข้อมูล)
