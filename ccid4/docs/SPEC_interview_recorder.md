# สเปกสำหรับ Claude Code: ระบบบันทึกเสียงสอบปากคำ (บก.สอท.4)

## บทบาทและวิธีทำงาน
คุณคือนักพัฒนาที่จะสร้างเว็บแอปภายในหน่วยงานตำรวจตามสเปกนี้
- อ่านสเปกทั้งหมดก่อน แล้วสรุปแผนงาน โครงสร้างโปรเจกต์ และสิ่งที่ยังไม่ชัดให้ผมอนุมัติก่อนเขียนโค้ด
- ทำทีละเฟส จบแต่ละเฟสให้รันเทสต์ บอกวิธีลองใช้ แล้วรอผมยืนยันก่อนไปต่อ
- เรื่องไหนไม่แน่ใจ (โดยเฉพาะแบบฟอร์มราชการและข้อกฎหมาย) ให้ถามผม ห้ามเดา
- หน้าจอเป็นภาษาไทย ส่วนโค้ดและคอมเมนต์เป็นภาษาอังกฤษ

## ที่มาและจุดยืนของระบบ
หน่วยงานใช้ระบบ MetaCops อยู่แล้ว ระบบนั้นรับแจ้งความออนไลน์ (ประชาชนพูดกับ AI ได้) และร่างคำให้การแบบถาม-ตอบจาก "ข้อเท็จจริงในคดี" แต่:
- คำให้การผู้ต้องหาถูกร่างตามแนวที่เลือก (รับสารภาพ/ปฏิเสธ) ไม่ได้มาจากคำพูดจริงของผู้ต้องหา
- เสียงรองรับแค่ฝั่งประชาชนแจ้งความ แบบกดค้างพูดทีละประโยค คนพูดคนเดียว และไม่เก็บไฟล์เสียง
- ประมวลผล AI ผ่านบริการภายนอก และส่งออกเป็น Word เท่านั้น

ระบบนี้ไม่ได้ทำซ้ำ MetaCops แต่เติมช่องว่าง: **บันทึกเสียงการสอบปากคำจริงในห้องสอบสวน (หลายคนพูด) แล้วถอดเป็นคำให้การแบบถาม-ตอบจากคำพูดจริง ตรวจย้อนกับเสียงได้ทุกคำตอบ เก็บเสียงต้นฉบับเป็นหลักฐาน ส่งออก PDF/Word และทุกอย่างรันบนเครื่องของหน่วยงาน**

## หลักการที่ห้ามละเมิด
1. **AI ร่าง คนตรวจ** พนักงานสอบสวนต้องตรวจและกดยืนยันก่อนส่งออกฉบับจริงทุกครั้ง
2. **ห้ามแต่งเนื้อหา** ทุกคำตอบในคำให้การต้องมาจากช่วงเสียงที่ระบุได้ ข้อความที่หาต้นทางไม่เจอต้องถูกติดธง
3. **เสียงต้นฉบับห้ามถูกแก้** เก็บแบบอ่านอย่างเดียว พร้อม SHA-256 ตั้งแต่ตอนปิดการบันทึก
4. **ข้อความถอดเสียงจาก AI ต้นฉบับเก็บไว้เสมอ** การแก้ไขทุกครั้งเก็บเป็นประวัติ (ใคร แก้อะไร เมื่อไร)
5. **ห้ามเรียกบริการภายนอก** ทั้งตอนใช้งานและตอนรันโมเดล (ดาวน์โหลดโมเดลครั้งเดียวตอนติดตั้ง แล้วตั้ง `HF_HUB_OFFLINE=1`)

## เทคโนโลยี
- Python 3.12, Django 5, PostgreSQL 16, Celery + Redis (ใช้ stack เดียวกับระบบหมายเรียกของหน่วยงาน เผื่อรวมกันภายหลัง)
- หน้าเว็บ: Django templates + HTMX + Alpine.js + Tailwind, แสดงคลื่นเสียงด้วย wavesurfer.js
- อัดเสียงในเบราว์เซอร์: MediaRecorder API (webm/opus) อัปโหลดเป็นท่อนทุก 5 วินาที
- จัดการไฟล์เสียง: ffmpeg (เก็บไฟล์ต้นฉบับ + แปลงเป็น FLAC 16 kHz mono สำหรับถอดเสียง)
- ถอดเสียง: Typhoon Whisper Large v3 (`typhoon-ai/typhoon-whisper-large-v3`, MIT) โหมดเร็วใช้ Typhoon Whisper Turbo
  - ประเมินว่าควรแปลงเป็น CTranslate2 แล้วใช้ faster-whisper (เร็วกว่า มี VAD และ word timestamp) หรือใช้ transformers pipeline
  - ต้องได้ timestamp ระดับคำ และค่าความมั่นใจรายคำ
  - ใช้ VAD (เช่น Silero) ตัดช่วงเงียบ ลดปัญหา Whisper แต่งข้อความตอนเงียบ และติดธงข้อความที่ซ้ำผิดปกติ
- แยกผู้พูด: pyannote.audio (โหลดโมเดลครั้งเดียวแล้วรันออฟไลน์)
- เรียบเรียงถาม-ตอบ: LLM ภาษาไทยแบบ open-weight รันผ่าน Ollama หรือ vLLM ในเครื่อง (เช่นตระกูล Typhoon) เลือกรุ่นที่ใส่ในการ์ดจอได้ และบังคับให้ตอบเป็น JSON ตาม schema
- ตรวจความตรงกับต้นทาง: เขียนเป็นโค้ด (rapidfuzz + กติกา) ห้ามใช้ LLM ตรวจตัวเองอย่างเดียว
- เอกสาร: python-docx + docxcompose, แปลง PDF ด้วย LibreOffice headless, ฟอนต์ TH SarabunIT๙ จากโฟลเดอร์ `fonts/`
- ติดตั้ง: Docker Compose (web, worker-cpu, worker-gpu, db, redis, ollama) ใช้ NVIDIA Container Toolkit สำหรับ worker-gpu
- ฮาร์ดแวร์เป้าหมาย: การ์ดจอ VRAM ประมาณ 16 GB ขึ้นไป และต้องมีโหมดสำรองบน CPU (ใช้ Turbo ช้าแต่ใช้ได้)
- **ข้อควรระวัง:** เบราว์เซอร์อนุญาตให้ใช้ไมค์เฉพาะ HTTPS หรือ localhost ต้องตั้ง HTTPS บนเครือข่ายภายใน (เช่น cert จาก CA ภายใน) และเขียนวิธีไว้ใน README

## ขั้นตอนการใช้งาน
1. **สร้างการสอบปากคำ:** ผูกกับเลขรับแจ้ง/เลขคดี, ฐานะผู้ให้การ (ผู้ต้องหา/ผู้กล่าวหา/พยาน), ข้อมูลผู้ให้การ, ผู้เข้าร่วม (พนักงานสอบสวน, ทนายหรือผู้ไว้วางใจ, ล่าม พร้อมภาษา), สถานที่ แล้วทดสอบไมค์ (แถบระดับเสียง + อัด 5 วินาทีแล้วเล่นกลับ)
2. **ก่อนเริ่ม (ผู้ต้องหา):** แสดงสคริปต์ให้พนักงานสอบสวนอ่านออกเสียง ซึ่งถูกบันทึกด้วย
   - แจ้งว่ามีการบันทึกเสียง
   - แจ้งข้อกล่าวหา (ป.วิ.อ. ม.134)
   - แจ้งสิทธิตาม ม.134/4: มีสิทธิให้การหรือไม่ก็ได้ ถ้าให้การ ถ้อยคำอาจใช้เป็นพยานหลักฐานได้ และมีสิทธิให้ทนายความหรือผู้ซึ่งตนไว้วางใจเข้าฟังการสอบปากคำ
   - ข้อความสคริปต์แก้ได้ในหน้าตั้งค่า (ให้พี่เลี้ยงตรวจถ้อยคำ)
3. **บันทึก:** ตัวจับเวลา แถบระดับเสียง ปุ่มพัก/ต่อ ปุ่ม "ทำเครื่องหมาย" (พร้อมหมายเหตุสั้น) แสดงสถานะ "บันทึกขึ้นเซิร์ฟเวอร์แล้วถึงนาทีที่ xx" ถ้าเบราว์เซอร์ปิดหรือเน็ตหลุด ท่อนที่ส่งแล้วต้องไม่หาย และกลับมาบันทึกต่อได้
4. **ปิดการบันทึก:** รวมท่อน → ไฟล์ต้นฉบับ → คำนวณ SHA-256 → ล็อกไฟล์ → เข้าคิวประมวลผล
5. **ประมวลผล (แสดงความคืบหน้าทีละขั้น):** VAD → ถอดเสียง → แยกผู้พูด → จับคำกับผู้พูด → ตรวจการแจ้งสิทธิ → ร่างถาม-ตอบ → ตรวจความตรงกับต้นทาง
6. **ตรวจข้อความถอดเสียง:**
   - ข้อความแยกตามผู้พูด คู่กับคลื่นเสียง กดคำไหนเล่นเสียงตรงนั้น ระหว่างเล่นไฮไลต์คำที่กำลังพูด
   - กำหนดว่า "ผู้พูด 1/2/3" คือใคร
   - คำที่ความมั่นใจต่ำ ตัวเลข เลขบัญชี ชื่อคน วันที่ และจำนวนเงิน ไฮไลต์ให้ตรวจ
   - แก้ข้อความได้ แต่เก็บต้นฉบับและประวัติ
7. **ร่างคำให้การแบบถาม-ตอบ:**
   - คำถามมาจากช่วงที่พนักงานสอบสวนพูด คำตอบมาจากช่วงที่ผู้ให้การพูด
   - เปลี่ยนสรรพนามผู้ให้การเป็น "ข้าฯ" ตามแบบราชการ, ตัดคำซ้ำหรือคำติดปาก (เอ่อ อ่า) ได้ แต่ห้ามเปลี่ยนความหมาย ห้ามสรุปรวบ ห้ามเติมข้อเท็จจริง
   - มี 2 ระดับให้เลือก: "ใกล้คำพูด" (ค่าเริ่มต้น) และ "ภาษาเขียน" (ปรับไวยากรณ์เล็กน้อย)
   - ทุกคู่ถาม-ตอบมีป้ายเวลา กดแล้วเล่นช่วงเสียงนั้น
   - ธงเตือน: ตัวเลขหรือชื่อที่ไม่พบในข้อความถอดเสียง, ประโยคที่หาช่วงต้นทางไม่ได้, ช่วงที่ผู้ให้การพูดแต่ไม่ได้อยู่ในคำตอบใด
   - แถบตรวจการแจ้งสิทธิ: แต่ละข้อแสดงว่าพบหรือไม่ พร้อมเวลาในเสียง ถ้าไม่พบให้เตือนชัดเจนก่อนยืนยัน
8. **ยืนยันและส่งออก:**
   - พนักงานสอบสวนกดยืนยัน → ล็อกเป็นเวอร์ชัน → ส่งออก Word และ PDF
   - เอกสารมีหัวกระดาษตามแบบฟอร์ม, ย่อหน้าการแจ้งสิทธิ, ถาม-ตอบ, บล็อกล่าม (ถ้ามี), หัว "ใบต่อคำให้การ" พร้อมชื่อผู้ให้การในหน้าถัดไป, ช่องลงนาม (ผู้ให้การ, พนักงานสอบสวน, ทนาย/ผู้ไว้วางใจ, ล่าม, ผู้บันทึก) และข้อความ "ได้อ่านให้ฟังแล้ว รับว่าถูกต้อง"
   - ท้ายเอกสารพิมพ์รหัสเอกสาร และ SHA-256 ของไฟล์เสียง
   - **ชุดหลักฐาน (ZIP):** ไฟล์เสียงต้นฉบับ, ข้อความถอดเสียงพร้อมเวลา (PDF + JSON), คำให้การ PDF, manifest ค่า hash ทุกไฟล์

## แบบฟอร์ม
- ผมจะขอแบบฟอร์ม "บันทึกคำให้การผู้ต้องหา/ผู้กล่าวหา/พยาน" จากพี่เลี้ยงมาให้ภายหลัง
- ระหว่างนี้ให้สร้างแบบฟอร์มชั่วคราวใน `templates_docx/` ที่ใช้ตัวแทนรูปแบบ `{ชื่อช่อง}` (แบบเดียวกับระบบหมายเรียก) และเขียนหน้ารวมรายการตัวแทนที่รองรับ
- เมื่อได้แบบฟอร์มจริง ต้องเปลี่ยนได้โดยแก้แค่ไฟล์ Word ไม่ต้องแก้โค้ด
- ตัวแทนต้องรองรับข้อความที่ถูกแบ่งหลาย run, ตาราง, กล่องข้อความ, header/footer และห้ามมี `{...}` หลุดในเอกสารที่ส่งออก
- ส่วนถาม-ตอบเป็นข้อมูลหลายแถว ให้ออกแบบเป็นบล็อกที่ทำซ้ำได้ในแบบฟอร์ม

## โมเดลข้อมูล (ปรับได้ แต่ต้องครอบคลุม)
- InterviewSession: คดี, ฐานะผู้ให้การ, ข้อมูลผู้ให้การ, สถานที่, สถานะ (ร่าง/กำลังบันทึก/กำลังประมวลผล/รอตรวจ/ยืนยันแล้ว), ผู้สร้าง
- Participant: บทบาท (พนักงานสอบสวน/ผู้ให้การ/ทนาย/ผู้ไว้วางใจ/ล่าม), ชื่อ, ภาษา
- Recording + RecordingChunk: ไฟล์ต้นฉบับ, ไฟล์สำหรับถอดเสียง, ความยาว, SHA-256, เวลาเริ่ม-จบ, เครื่องหมาย (marker)
- TranscriptSegment + Word: เวลาเริ่ม-จบ, ผู้พูด, ข้อความ AI ต้นฉบับ, ข้อความปัจจุบัน, ความมั่นใจ
- TranscriptEdit: ประวัติการแก้
- SpeakerMapping: ผู้พูดจาก diarization → Participant
- RightsCheck: รายการสิทธิ, พบหรือไม่, ช่วงเวลา, ผู้ยืนยัน
- StatementDraft (มีเวอร์ชัน) + QAPair: ลำดับ, คำถาม, คำตอบ, ช่วงต้นทาง (segment ids + เวลา), ธงเตือน
- GeneratedDocument: ประเภท, ไฟล์ docx/pdf, hash, เวอร์ชันร่างที่ใช้
- AuditLog: สร้าง, บันทึก, เล่นเสียง, ดาวน์โหลด, แก้ไข, ยืนยัน, ส่งออก
- RetentionPolicy: ระยะเวลาเก็บ (ตั้งค่าได้)

## ความปลอดภัยและ PDPA
- ล็อกอินทุกหน้า สิทธิ์ตามบทบาท และพนักงานสอบสวนเห็นเฉพาะการสอบปากคำของตัวเอง ยกเว้นหัวหน้าและผู้ดูแลระบบ
- เก็บไฟล์เสียงบนดิสก์ที่เข้ารหัส (เขียนวิธีตั้ง BitLocker/LUKS ใน README) และเปิดเล่นผ่านแอปเท่านั้น ห้ามมีลิงก์ไฟล์ตรง
- บันทึก AuditLog ทุกครั้งที่เล่นหรือดาวน์โหลดเสียง
- ลบหรือย้ายเข้าคลังตามระยะเวลาที่ตั้งไว้ โดยต้องมีผู้อนุมัติ
- ห้าม commit ไฟล์เสียงหรือข้อมูลจริงเข้า git

## ข้อมูลทดสอบ
- ห้ามใช้เสียงผู้ต้องหาจริง ใช้เสียงสวมบทบาทที่เจ้าหน้าที่อัดให้ (ผมจะเตรียมให้ภายหลัง)
- ระหว่างนี้ให้สร้าง fixture เป็นข้อความถอดเสียงสมมติ (JSON มีผู้พูด เวลา คำ และความมั่นใจ) ของการสอบปากคำผู้ต้องหาคดีขายบัญชีม้า ประมาณ 25 ช่วงพูด มีช่วงแจ้งสิทธิครบ มีเลขบัญชี จำนวนเงิน และวันที่ เพื่อใช้เทสต์ส่วนร่างถาม-ตอบ ตรวจต้นทาง และสร้างเอกสาร โดยไม่ต้องรันโมเดลเสียง
- สร้าง fixture อีกชุดที่ไม่มีการแจ้งสิทธิ เพื่อทดสอบว่าระบบเตือน
- เขียนสคริปต์ประเมินผล: คำนวณ CER ของการถอดเสียงเทียบกับข้อความที่คนพิมพ์ เปรียบเทียบ Large v3 กับ Turbo และรายงานเวลาประมวลผลต่อนาทีเสียง

## เฟสการพัฒนา
1. โครงโปรเจกต์, Docker Compose (มี worker-gpu แบบว่างไว้ก่อน), ล็อกอิน, โมเดลข้อมูล, หน้าสร้างและรายการการสอบปากคำ, HTTPS ภายใน
2. หน้าบันทึกเสียง: อัปโหลดเป็นท่อน, กลับมาบันทึกต่อได้, เครื่องหมาย, ปิดการบันทึก + SHA-256 + ล็อกไฟล์, เล่นเสียงย้อนหลัง
3. ไปป์ไลน์ VAD + ถอดเสียง + แยกผู้พูด + หน้าตรวจข้อความ (sync กับเสียง, ไฮไลต์, กำหนดผู้พูด, ประวัติการแก้)
4. ร่างถาม-ตอบด้วย LLM + ตรวจต้นทางด้วยโค้ด + ตรวจการแจ้งสิทธิ (ทดสอบด้วย fixture)
5. แบบฟอร์มชั่วคราว + ส่งออก Word/PDF + ใบต่อคำให้การ + บล็อกล่าม + ชุดหลักฐาน ZIP
6. ตั้งค่า (สคริปต์แจ้งสิทธิ, แบบฟอร์ม, ระยะเก็บ), AuditLog, สคริปต์ประเมินผล, README ภาษาไทย

## เกณฑ์ตรวจรับ
- บันทึกเสียง 10 นาที แล้วปิดแท็บกลางคัน: ท่อนที่อัปโหลดแล้วไม่หาย และบันทึกต่อได้
- ไฟล์เสียงหลังปิดการบันทึก: SHA-256 ตรงกับที่พิมพ์ในเอกสาร และแก้ไขผ่านแอปไม่ได้
- fixture คดีบัญชีม้า: ทุกคู่ถาม-ตอบมีช่วงต้นทาง, เลขบัญชีและจำนวนเงินในร่างตรงกับข้อความถอดเสียง 100%
- ถ้าแก้ร่างให้มีตัวเลขที่ไม่อยู่ในเสียง ระบบต้องขึ้นธงเตือน
- fixture ที่ไม่มีการแจ้งสิทธิ: ระบบเตือนและต้องกดยืนยันแบบระบุเหตุผลก่อนส่งออก
- PDF และ Word ไม่มี `{` หลงเหลือ, หน้าที่ 2 เป็นต้นไปมีหัว "ใบต่อคำให้การ" และชื่อผู้ให้การ
- ระหว่างใช้งานทั้งหมด ไม่มี request ออกไปนอกเครื่อง (เขียนเทสต์ที่บล็อกเครือข่ายภายนอกแล้วรันไปป์ไลน์ได้)

เริ่มจากสรุปแผนงานและโครงสร้างโปรเจกต์ให้ผมดูก่อน
