# คู่มือติดตั้งและใช้งาน CCID4

ระบบช่วยพนักงานสอบสวน กก.1 บก.สอท.4 · ฉบับปรับปรุง 18 พ.ย. 2569 (ตรงกับระบบถึงเฟส 11)

> **อ่านก่อน**
> - ข้อมูลคดีและข้อมูลบุคคลจริงต้องอยู่ในเครื่องหรือเซิร์ฟเวอร์ของหน่วยเท่านั้น
> - ระบบสาธิตบน Vercel ใช้ข้อมูลจำลองเท่านั้น ห้ามกรอกหรืออัดเสียงข้อมูลจริง
> - AI ทุกตัว (ถอดเสียง อ่านเอกสาร ร่างข้อความ) รันในเครื่องของหน่วย ไม่ส่งข้อมูลออกนอกเครือข่าย
> - ทุกสิ่งที่ AI ร่างต้องให้พนักงานสอบสวนตรวจและกดยืนยันก่อนใช้

## 4. ติดตั้งแบบเครื่องเดียว (ทดลองใช้งานจริง)

ขั้นตอนละเอียดพร้อมภาพรวมการใช้ห้องสอบปากคำอยู่ใน [`ติดตั้งบนเครื่องเพื่อทดสอบ.md`](ติดตั้งบนเครื่องเพื่อทดสอบ.md) สรุปสั้นได้ดังนี้

1. ติดตั้งและเปิด **Docker Desktop** รอจนขึ้น *Engine running*
2. ดาวน์โหลดโค้ดจาก GitHub (Code → Download ZIP แล้วแตกไฟล์) หรือ:

   ```bash
   git clone https://github.com/WoravitSuwan/smart-ccid4.git
   ```
3. เปิด Terminal ในโฟลเดอร์ `ccid4` แล้วรันคำสั่งของระบบปฏิบัติการที่ใช้
   - Windows:

     ```bash
     powershell -ExecutionPolicy Bypass -File scripts\install_local.ps1
     ```
   - macOS/Linux:

     ```bash
     bash scripts/install_local.sh
     ```
4. ตัวติดตั้งทำงานตามลำดับนี้
   1. สร้าง `.env` พร้อมรหัสสุ่ม
   2. สร้างโปรแกรม
   3. โหลดโมเดลถอดเสียง (ค่าเริ่มต้น `large-v3-turbo`)
   4. เปิดระบบ
   5. ถามข้อมูลเพื่อสร้างบัญชีพนักงานสอบสวนคนแรก (ชื่อ-นามสกุลพิมพ์ภาษาไทยได้ · ชื่อผู้ใช้และรหัสผ่านต้องเปลี่ยนแป้นเป็นภาษาอังกฤษก่อนพิมพ์ รหัสผ่านอย่างน้อย 12 ตัว และขณะพิมพ์จะไม่เห็นตัวอักษร)
5. เปิด `http://localhost:8000` ด้วย Chrome หรือ Edge

ต้องการเมนูของหัวหน้า (เช่น เทมเพลตเอกสาร) บนเครื่องเดียว ให้สร้างบัญชีหัวหน้าเพิ่ม:

```bash
docker compose -f docker-compose.local.yml exec web python manage.py create_officer --role supervisor
```

## 5. ติดตั้งบนเซิร์ฟเวอร์ของหน่วย (ใช้ร่วมกันหลายเครื่อง)

### 5.1 เตรียมเซิร์ฟเวอร์ (Ubuntu)

ติดตั้ง Docker Engine และ Compose plugin ตามคู่มือของ Docker สำหรับ Ubuntu แล้วตรวจว่าใช้ได้:

```bash
docker compose version
```

เปิดไฟร์วอลล์เฉพาะพอร์ต 443 (HTTPS) และ 80 (ส่งต่อไป HTTPS) ให้เครื่องในวงแลนของหน่วย ไม่ต้องเปิดพอร์ตอื่น

### 5.2 ดาวน์โหลดโค้ดและตั้งค่า

```bash
git clone https://github.com/WoravitSuwan/smart-ccid4.git
```

```bash
cd smart-ccid4/ccid4 && cp .env.example .env
```

แก้ไฟล์ `.env` (ห้าม commit ไฟล์นี้) อย่างน้อยค่าต่อไปนี้

| ตัวแปร | ตั้งเป็น |
|---|---|
| `DJANGO_SECRET_KEY` | ค่าสุ่มยาว 50 ตัวขึ้นไป สร้างได้ด้วย `python3 -c "import secrets;print(secrets.token_urlsafe(50))"` · **ห้ามเปลี่ยนหลังใช้งานแล้ว** (ดูหัวข้อ 10.5) |
| `POSTGRES_PASSWORD` | รหัสผ่านฐานข้อมูลที่สุ่มขึ้นมา |
| `DATABASE_URL` | `postgres://ccid4:<รหัสเดียวกับบรรทัดบน>@db:5432/ccid4` |
| `CCID4_HOST` | ชื่อที่ผู้ใช้พิมพ์เปิดระบบ เช่น `ccid4.local` |
| `DJANGO_ALLOWED_HOSTS` | ชื่อเดียวกับ `CCID4_HOST` เช่น `ccid4.local` |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | `https://ccid4.local` |
| `CCID4_UNIT_NAME`, `CCID4_UNIT_SHORT` | ชื่อหน่วยเต็มและชื่อย่อ |
| `CCID4_DEMO_MODE` | `false` |
| `CCID4_PUBLIC_URL` | ที่อยู่ที่ประชาชนเปิดได้ สำหรับพิมพ์ลง QR แจ้งความและลิงก์ติดตาม (ถ้ายังไม่มีเว้นว่าง) |
| `CCID4_DAILY_DIGEST`, `EMAIL_HOST` … | เปิดสรุปรายวันทางอีเมลผ่าน SMTP ภายในหน่วย (หัวข้อ 5.7) |

ตัวแปรทั้งหมดอธิบายไว้ในภาคผนวก 13.1

### 5.3 เปิดระบบ

```bash
make up
```

ถ้าเครื่องไม่มี `make` ใช้คำสั่งนี้แทน:


### 5.4 ชื่อเครื่องและใบรับรอง HTTPS

เบราว์เซอร์ยอมให้ใช้ไมโครโฟนเฉพาะ HTTPS (หรือ localhost) จึงต้องตั้ง 2 อย่าง

**ก. ให้ทุกเครื่องรู้จักชื่อ `ccid4.local`** เลือกวิธีใดวิธีหนึ่ง
- ให้ฝ่ายเครือข่ายเพิ่มชื่อใน DNS ภายในของหน่วย ชี้ไปที่ IP ของเซิร์ฟเวอร์
- หรือแก้ไฟล์ hosts ของแต่ละเครื่อง เพิ่มบรรทัด `192.168.x.x  ccid4.local`
  - Windows: `C:\Windows\System32\drivers\etc\hosts`
  - macOS/Linux: `/etc/hosts`

**ข. ให้ทุกเครื่องเชื่อใบรับรองของระบบ** ระบบใช้ Caddy ออกใบรับรองภายใน (`deploy/Caddyfile`, `tls internal`) คัดลอกใบรับรองรากออกมาจากเซิร์ฟเวอร์:

```bash
docker compose cp proxy:/data/caddy/pki/authorities/local/root.crt ./ccid4-root.crt
```

นำ `ccid4-root.crt` ไปติดตั้งบนเครื่องผู้ใช้
- **Windows:** ดับเบิลคลิกไฟล์ → Install Certificate → Local Machine → Place all certificates in → *Trusted Root Certification Authorities*
- **macOS:** เปิดด้วย Keychain Access → System → ดับเบิลคลิกใบรับรอง → Trust → *Always Trust*
- **Chrome บน Linux:** Settings → Privacy and security → Security → Manage certificates → Authorities → Import

ถ้าหน่วยมีใบรับรองของตัวเอง ให้แก้ `deploy/Caddyfile` เป็น `tls /certs/ccid4.crt /certs/ccid4.key` แล้ว mount โฟลเดอร์ใบรับรองเข้า `proxy`

### 5.6 ถอดเสียงสำหรับห้องสอบปากคำ

เลือกตามเครื่องที่มี

**CPU (ไม่มี GPU):**
1. ใน `.env` ตั้งค่าต่อไปนี้ (`ASR_MODEL` ใส่ในขั้นที่ 3)

   ```
   CCID4_WITH_ASR=true
   ASR_BACKEND=whisper
   ASR_DEVICE=cpu
   ASR_COMPUTE_TYPE=int8
   ```
2. สร้างใหม่:

   ```bash
   docker compose up -d --build
   ```
3. โหลดโมเดล (ครั้งเดียว) แล้วนำบรรทัด `ASR_MODEL=...` ที่คำสั่งพิมพ์ออกมาใส่ใน `.env`:

   ```bash
   docker compose run --rm -e HF_HUB_OFFLINE=0 worker python manage.py setup_asr --model large-v3-turbo
   ```
4. เปิดระบบใหม่:

   ```bash
   docker compose up -d
   ```

**GPU (NVIDIA):**
1. ติดตั้ง NVIDIA Container Toolkit บนเซิร์ฟเวอร์
2. ใน `.env` ตั้ง `ASR_BACKEND=whisper` และ `CCID4_ASR_QUEUE=true`
3. โหลดโมเดล:

   ```bash
   docker compose --profile gpu run --rm -e HF_HUB_OFFLINE=0 worker-gpu python manage.py setup_asr --model large-v3
   ```
4. ใส่บรรทัด `ASR_MODEL=...` ที่ได้ลงใน `.env` แล้วเปิดระบบพร้อม worker GPU:

   ```bash
   docker compose --profile gpu up -d
   ```

**Typhoon Whisper (แม่นภาษาไทยที่สุด):** ต้องแปลงโมเดลก่อน ดูชื่อรุ่นในหน้า Hugging Face ของ Typhoon แล้วใช้ `setup_asr --model <ชื่อรุ่น> --convert` ตามที่อธิบายใน [`ติดตั้งบนเครื่องเพื่อทดสอบ.md`](ติดตั้งบนเครื่องเพื่อทดสอบ.md)

**แยกผู้พูดอัตโนมัติ (ไม่บังคับ, GPU):** วาง pipeline ของ pyannote ใน volume `models` แล้วตั้ง `DIARIZATION_MODEL=/models/pyannote` · ถ้าไม่ตั้ง ระบบเดาผู้พูดจากประโยค และพนักงานสอบสวนแก้รายช่วงได้

หลังโหลดโมเดลแล้วระบบทำงานออฟไลน์ (`HF_HUB_OFFLINE=1`)


### 5.7 อีเมลสรุปรายวัน (ไม่บังคับ)

ใช้เมื่อหน่วยมีเซิร์ฟเวอร์อีเมลภายใน ใส่ใน `.env` แล้วสั่ง `docker compose up -d`:

```
CCID4_DAILY_DIGEST=true

EMAIL_HOST=<เซิร์ฟเวอร์อีเมลของหน่วย>
```

- ระบบส่งทุกเช้า 07.17 น. เฉพาะผู้ใช้ที่ติ๊ก "รับสรุปรายวัน" ในหน้าภาพรวม
- ในอีเมลมีเฉพาะจำนวนและเลขคดี ไม่มีชื่อหรือเลขบัตร
- **ช่องทางภายนอก** (เช่น ส่งไปห้องแชต) ปิดไว้ เพราะเป็นการส่งข้อมูลออกนอกเครือข่าย
  - เปิดได้เมื่อได้รับอนุมัติเท่านั้น: `CCID4_EXTERNAL_CHANNELS=webhook` และ `CCID4_WEBHOOK_URL=<ปลายทาง>`
  - ระบบส่งเฉพาะหัวข้อสั้น ๆ

## 6. เปิดใช้ AI ในเครื่อง (ไม่บังคับ)

ถ้าไม่เปิด ระบบยังใช้ได้ครบ โดยใช้กติกาในโค้ดดึงข้อมูลจากที่กรอกหรือพูดแทน AI (ค่า `AI_BACKEND=fake`)

1. เปิด Ollama:

   ```bash
   docker compose --profile ai up -d ollama
   ```
2. โหลดโมเดลภาษาไทยแบบ open-weight ที่หน่วยเลือก (ครั้งเดียว ขณะต่ออินเทอร์เน็ต):

   ```bash
   docker compose exec ollama ollama pull <ชื่อโมเดล>
   ```
3. โหลดโมเดลทำ embedding สำหรับค้นฎีกา:

   ```bash
   docker compose exec ollama ollama pull bge-m3
   ```
4. ใน `.env` ตั้งค่า แล้วสั่ง `docker compose up -d` ใหม่

   ```
   AI_BACKEND=ollama
   OLLAMA_MODEL=<ชื่อโมเดล>
   OLLAMA_EMBED_MODEL=bge-m3
   ```
5. OCR ภาพ (บัตร บันทึกจับกุม สลิป): โหลดโมเดลอ่านภาพ แล้วตั้ง `OCR_BACKEND=ollama` และ `OCR_MODEL=<ชื่อโมเดล>`
6. นำเข้าฎีกาจากแหล่งที่หน่วยมีสิทธิ์ใช้ (ห้ามดึงจากเว็บไซต์โดยไม่ได้รับอนุญาต):

   ```bash
   docker compose exec web python manage.py import_dika /data/dika.json --source "ชื่อชุดข้อมูล"
   ```

## 7. ตั้งค่าครั้งแรกหลังติดตั้ง

ทำตามลำดับ (ใช้เวลาราว 30 นาที)

1. **สร้างผู้ดูแลระบบคนแรก** (แบบเซิร์ฟเวอร์):

   ```bash
   docker compose exec web python manage.py createsuperuser
   ```

   เข้า `https://ccid4.local/django-admin/` → Users → เลือกบัญชีนั้น → บทบาท = **ผู้ดูแลระบบ** → บันทึก
2. **เข้าสู่ระบบครั้งแรกด้วยผู้ดูแล** ระบบพาไปตั้งยืนยันตัวตน 2 ขั้น (TOTP)
   - สแกน QR ด้วยแอป Authenticator บนมือถือ (เช่น Google Authenticator หรือ Microsoft Authenticator)
   - ผู้ดูแลระบบต้องใช้ 2 ขั้นทุกครั้ง
3. **สร้างผู้ใช้ทุกคน:** เมนู "ตั้งค่าระบบ" → "ผู้ใช้และสิทธิ์" (หน้า `/django-admin/accounts/user/`)
   - กำหนดบทบาท (หัวข้อ 8) ยศ ชื่อ นามสกุล ตำแหน่ง กลุ่มงาน และวันหมดอายุบัญชี
   - **กลุ่มงาน** ต้องตรงกันระหว่างหัวหน้ากับลูกทีม หัวหน้าจึงเห็นคดีของทีม
   - ติ๊ก "บังคับยืนยันตัวตน 2 ขั้น" รายคนได้
   - อีกวิธี:

     ```bash
     docker compose exec web python manage.py create_officer
     ```
4. **พนักงานสอบสวนทุกคนกรอก "ข้อมูลพื้นฐานของฉัน"** ให้ครบ 5 ส่วน จนวงแหวนเป็น 100%: ข้อมูลส่วนตัว · ผู้บังคับบัญชา · หน่วยงาน · ชุดจับกุม · ศาล/อัยการ
   - เอกสารหลายฉบับจะ "ยังไม่พร้อม" ถ้าส่วนนี้ไม่ครบ
5. **หัวหน้างานสอบสวน / ฝ่ายกฎหมายตรวจกติกากำหนดเวลา** ที่ `/django-admin/deadlines/deadlinerule/`
   - ค่าตั้งต้นทุกตัวมีป้าย "รอฝ่ายกฎหมายตรวจทาน" โดยเฉพาะผัดฟ้องและการนับวันแรก
   - ทุกการแก้เก็บเป็นฉบับใหม่
6. **ตั้งค่าห้องสอบปากคำ** (เมนูห้องสอบปากคำ → ตั้งค่า): สคริปต์แจ้งสิทธิที่อ่านออกเสียง ระยะเก็บไฟล์เสียง และแบบฟอร์มคำให้การของหน่วย (ถ้ามี)
7. **ตั้งค่าหมายเรียก** (เมนูหมายเรียก → ตั้งค่า): ยศเต็ม ชื่อลงนาม และตำแหน่งของพนักงานสอบสวนแต่ละคน · สถานที่ออกหมาย · สถานที่นัด · ที่อยู่ผู้ส่ง · แบบฟอร์มหมาย
8. **อัปโหลดแบบฟอร์มของหน่วย** (ถ้าต้องการถ้อยคำต่างจากมาตรฐาน) ที่เมนู "เทมเพลตเอกสาร" (หัวข้อ 9.13)
9. **ติดตั้ง card-agent** บนเครื่องที่มีเครื่องอ่านบัตรประชาชน (หัวข้อ 9.17)

## 9. การใช้งานรายเมนู

### 9.1 เข้าสู่ระบบและส่วนกลาง
- **แถบบน**
  - ช่องค้นหา
  - ป้าย "AI ในเครื่อง"
  - **กระดิ่ง:** แจ้งเตือนตัวระบุซ้ำข้ามคดี คำขอรวมสำนวน และไฟล์พยานหลักฐานที่ SHA-256 ไม่ตรง กดรายการเพื่อเปิด
  - ปุ่มดวงอาทิตย์: สลับธีมมืด/สว่าง ระบบจำค่าไว้
  - เมนูผู้ใช้: ตั้ง 2 ขั้นและออกจากระบบ
- **เมนูซ้าย** พับได้ (ปุ่ม "ย่อเมนู") · จุดสีส้มที่ "ข้อมูลพื้นฐานของฉัน" = ยังกรอกไม่ครบ

### 9.2 คดีของฉัน
- การ์ด 4 ใบด้านบน (ทั้งหมด / รับแจ้งใหม่ / กำลังสอบสวน / เสร็จสิ้น) กดเพื่อกรอง
- แท็บประเภทคดี (อาญา / ออนไลน์ / จราจร) และช่องค้นหาที่เปลี่ยนผลทันทีระหว่างพิมพ์
- "สร้างคดี" เพื่อเปิดคดีใหม่
- **ลบคดี:** ต้องพิมพ์เลขคดีและเหตุผล · ลบแบบกู้คืนได้ · มีบันทึกในประวัติการใช้งาน

### 9.3 หน้าคดี
- **หัวคดี:** เลขคดี สถานะ ประเภท ชิปกำหนดเวลาที่ใกล้ที่สุด และป้าย "เชื่อมโยงกับคดีอื่น n คดี" (ถ้ามี)
- **แท็บ**
  - ข้อมูลคดี · ผู้กล่าวหา (บัญชีทรัพย์ คำให้การ ประวัติแชท)
  - ผู้ต้องหา และพยาน: เพิ่มได้ไม่จำกัด แต่ละคนเป็นแท็บย่อย
  - พนักงานสอบสวน: หนังสือออกภายนอก บันทึกพนักงานสอบสวน
  - ค้นฎีกา
  - เส้นทางเงิน (เฉพาะคดีออนไลน์) · พยานหลักฐาน/ของกลาง
- **บันทึก:** ปุ่ม "บันทึก" ที่แถบล่างบันทึกทุกแท็บพร้อมกัน
  - ถ้าช่องไหนผิด จะไม่มีอะไรถูกบันทึก ระบบเปิดแท็บที่ผิดพร้อมจุดแดง
  - มีจุด "ยังไม่บันทึก" และเตือนก่อนออกจากหน้า
  - ปุ่มออกเอกสารถูกล็อกจนกว่าจะบันทึก
- **ข้อมูลอ่อนไหว:** เลขบัตรประชาชนแสดงแบบปิดบัง กด "แสดง" ต้องมีสิทธิ์และถูกบันทึก
- **ป้าย "พบในคดีอื่น"** ข้างบุคคลที่เบอร์โทรหรือเลขบัตรตรงกับคดีอื่น
- **แผงขวา "งานและกำหนดเวลา":** กำหนดเวลา (สีตามความเร่งด่วน) · สิ่งที่ต้องทำ · ทำแล้ว · ติ๊กหรือเพิ่มงานเองได้
- **Timeline คดี:** ปุ่มที่แถบล่าง เรียงทุกเหตุการณ์ ส่งออก PDF ได้

### 9.4 กำหนดเวลาและการควบคุมตัว
- กรอกโทษจำคุกสูงสุด (เดือน) และประเภทศาลในแท็บข้อมูลคดี
- แท็บผู้ต้องหา: ใส่ "วันเวลาถึงที่ทำการพนักงานสอบสวน" → นับถอยหลัง 48 ชม.
- กด "บันทึกฝากขังผัดที่ n": ระบบเติมวันเริ่มให้ ตรวจจำนวนวันตามกติกา แล้วแสดงผัดและวันที่เหลือ
  - ศาลแขวงเปลี่ยนเป็นผัดฟ้องให้เอง
- กำหนดที่ตรงวันหยุด ระบบบอกวันที่ต้องยื่นจริง

### 9.5 ออกเอกสารและรวมสำนวน
- **ออกเอกสาร:** หน้าคดี → "ออกเอกสาร"
  - เอกสารพร้อม = สว่าง ไม่พร้อม = จาง ชี้ดูว่าขาดอะไร กดชื่อข้อมูลที่ขาดเพื่อไปกรอก
  - เลือกหลายฉบับและเลือกบุคคลได้ · เลือก Word / PDF / ทั้งสอง · หลายไฟล์ได้ ZIP
  - ทุกครั้งเก็บไฟล์ ฉบับที่ เวอร์ชันเทมเพลต ผู้ออก และลงบันทึกพนักงานสอบสวนอัตโนมัติ
- **รวมสำนวนเป็น PDF เล่มเดียว:** ปุ่มในหน้าออกเอกสาร
  1. เลือกเอกสารที่ออกแล้ว คำให้การจากเสียง และพยานหลักฐาน PDF/ภาพ
  2. แก้ลำดับได้
  3. กด "รวมเป็น PDF" → ได้ไฟล์ที่มีสารบัญ เลขหน้า "หน้า n / N" และชื่อผู้ส่งออกกับเวลาทุกหน้า

### 9.6 AI ช่วยร่าง
ทุกผลจาก AI มีป้าย "ร่างโดย AI – รอตรวจ" จนกว่าจะกดยืนยัน และใช้ได้หลังบันทึกคดีแล้วเท่านั้น
- **แท็บข้อมูลคดี**
  - "ให้ AI วิเคราะห์ใหม่" → เสนอฐานความผิด มาตรา อัตราโทษ ศาล → "ใช้ค่าที่เสนอ" แล้วบันทึก
  - "สรุปพฤติการณ์" → ใช้ร่างแล้วแก้ต่อ
- **แท็บบุคคล:** ร่างคำให้การผู้กล่าวหา/พยาน
  - "ตรวจความสอดคล้อง" ติดธงจุดที่ไม่ตรงกับพฤติการณ์
  - ผู้ต้องหา: "แจ้งสิทธิและสอบคำให้การ" (ติ๊กแจ้งสิทธิ เลือกรับสารภาพ/ปฏิเสธ) → ร่าง → "ยืนยันคำให้การ"
- **ค้นฎีกา:** ผลอัตโนมัติจากฐานความผิด หรือค้นเองด้วยคำ/มาตรา · ปักหมุดเพื่อใส่ในรายงานการสอบสวน

### 9.7 รับแจ้งความและนำเข้าคดี
- **ลิงก์/QR ส่วนตัว** 2 แบบ (คดีทั่วไป / คดีเทคโนโลยี): คัดลอกลิงก์ ดาวน์โหลด QR หรือพิมพ์ป้าย A5
  - ประชาชนสแกนแล้ว "คุยกับผู้ช่วย" หรือกรอกฟอร์ม แนบหลักฐาน และยินยอมตาม PDPA
  - ระบบตั้งเป็นคดี "รับแจ้งใหม่" ในบัญชีเจ้าของลิงก์ทันที พร้อมประวัติแชท
- **ติดตามสถานะ:** ผู้แจ้งได้ลิงก์ติดตามอัตโนมัติ (จัดการลิงก์ได้ในหัวข้อ 9.16)
- **กรอกแทนผู้แจ้ง:** ฟอร์มเดียวกันในระบบภายใน บันทึกว่าใครกรอก
- **นำเข้าจากเอกสาร:** อัปโหลดบันทึกจับกุม/ปจว.จราจร (PDF หรือภาพ) → AI แยกข้อมูล → ตรวจทานเทียบต้นฉบับ → "สร้างคดี"
- หน้าสาธารณะจำกัดจำนวนครั้งต่อ IP และต่อลิงก์ เพื่อกันการก่อกวน

### 9.8 หมายเรียก (ธุรการ/หัวหน้า)
1. **นำเข้าข้อมูล:** อัปโหลด Excel ผู้แจ้งและทะเบียนคดี → เลือกชีต → จับคู่คอลัมน์ → ยืนยัน (นำเข้าซ้ำไม่เพิ่มแถวซ้ำ)
2. **ทะเบียนคดี:** กรองสถานะ ปี พนักงานสอบสวน · ปุ่มลัด "ยังไม่สิ้นสุด" "ยังไม่เคยออกหมาย" "ที่อยู่ไม่ครบ"
3. **ออกหมาย:** ติ๊กแถวหรือ "ออกให้ทุกคดีตามตัวกรอง" → ตรวจกลุ่มตามผู้ลงนาม → เลือกวันนัด → "ดูตัวอย่าง PDF" → ยืนยัน
   - เลือกรวมไฟล์เดียวหรือแยกรายคนได้ และพิมพ์ใบจ่าหน้าซองได้
4. **บันทึกผล:** บันทึกผลรายหมาย (มาตามนัด / ไม่มา) ที่หน้ารายละเอียดคดี
- รายการที่ไม่มีที่อยู่พอตาม ป.วิ.อาญา ม.53 จะไม่ออกหมายและบอกเหตุผล

### 9.9 ห้องสอบปากคำด้วยเสียง
1. **เริ่ม**
   - ผู้แจ้งรายใหม่: เมนูห้องสอบปากคำ → "อัดเสียงผู้แจ้งความรายใหม่" (กรอกชื่อ เรื่องย่อ) ระบบสร้างคดีให้
   - คนในคดีเดิม: หน้าคดี → แท็บบุคคล → "สอบด้วยเสียง"
2. **แจ้งผู้ให้ถ้อยคำว่ากำลังบันทึกเสียง** → ทดสอบไมค์ → "เริ่มบันทึก"
   - ใช้พัก / หยุด / ทำเครื่องหมายได้ระหว่างอัด
   - อัดยาวเป็นชั่วโมงได้ เสียงส่งขึ้นระบบทุก 5 วินาที ปิดแท็บแล้วกลับมา "บันทึกต่อ" ได้
3. **"ปิดการบันทึกและประมวลผล":** ไฟล์ถูกล็อกพร้อม SHA-256 และเข้าทะเบียนพยานหลักฐานอัตโนมัติ
4. **หน้าประมวลผล:** แสดงความคืบหน้าการถอดเสียง ถ้าไม่มีโมเดลถอดเสียง นำเข้าไฟล์ถอดเสียงจากเครื่องมืออื่นได้
5. **หน้าตรวจ**
   - คลื่นเสียง: กดคำเพื่อฟังช่วงนั้น
   - แก้ข้อความหรือผู้พูดรายช่วงได้ ระบบเก็บต้นฉบับไว้
   - กล่อง "สรุปจากเสียง" 3 แท็บ: สรุปใจความสำคัญ · เล่าเรื่อง (คำให้การแบบบรรยาย) · คำที่พบบ่อย
   - เลือกรูปแบบคำให้การ: บรรยาย หรือ ถาม–ตอบ
   - ติ๊ก "ฟังแล้ว ตรงกับเสียง"
6. **"ยืนยันและสร้าง Word/PDF":** ได้คำให้การ สรุปการสอบปากคำ และชุดหลักฐาน ZIP · คำให้การของบุคคลในคดีถูกแทนที่ด้วยฉบับนี้

### 9.10 เส้นทางเงินและบัญชีม้า (คดีออนไลน์)
หน้าคดี → แท็บ "เส้นทางเงิน" → "เปิดหน้าเส้นทางเงิน"
- **ธุรกรรม:** เพิ่มเองได้ 3 วิธี
  - กรอกเอง
  - "อ่านจากสลิป": AI กรอกให้ ต้องตรวจก่อนบันทึก
  - "นำเข้า statement" Excel/CSV: มีหน้าจับคู่คอลัมน์ และใส่บัญชีต้นทางของ statement ได้
- **บัญชีปลายทาง:** ชั้นของบัญชี ยอดรับ และสถานะ (ยังไม่ขอข้อมูล / ขอแล้ว / ระงับแล้ว / ได้ข้อมูลเจ้าของ)
  - ติ๊กหลายบัญชี → "ออกหนังสือที่เลือก" ได้หนังสือธนาคารละ 1 ฉบับใน ZIP
- **แผนภาพ:** ผู้เสียหาย → ชั้น 1 → ชั้น 2 คลิกบัญชีดูธุรกรรม ส่งออก PNG ได้
- **บัญชีออนไลน์/URL:** LINE ID, Facebook, เว็บไซต์ และอีเมลที่เกี่ยวข้อง
- **คริปโต:** กระเป๋า BTC/EVM/TRON (ตรวจรูปแบบในเครื่อง) ธุรกรรม และ "ส่งออก JSON (CryptoTrace)"
- **ยอดที่ผู้เสียหายโอนออก** ลงบัญชีทรัพย์ของผู้กล่าวหาให้อัตโนมัติ

### 9.11 เครือข่ายคดี
- กรองตามคดี ประเภทตัวระบุ และช่วงวันที่ · คลิกโหนดดูรายละเอียด · ดับเบิลคลิกคดีเพื่อเปิด
- คดีที่ไม่มีสิทธิ์ดูแสดงเป็นกรอบเส้นประ เห็นเฉพาะเลขคดีและพนักงานสอบสวนเจ้าของ (ติดต่อเจ้าของคดีเอง)
- ส่งออก PNG และ Excel ได้
- **"เสนอรวมสำนวน":** เลือกคดีในกราฟและใส่เหตุผล → หัวหน้าพิจารณาที่ "คำขอรวมสำนวน"

### 9.12 พยานหลักฐานและของกลาง
หน้าคดี → แท็บ "พยานหลักฐาน/ของกลาง" → "เปิดหน้าพยานหลักฐาน"
- **รับไฟล์:** เลือกได้หลายไฟล์ ระบุ "ได้มาจาก" ระบบคำนวณ SHA-256 และล็อกไฟล์
  - ลบไม่ได้ ใช้ "ถอนออกจากสำนวน" พร้อมเหตุผล
- **ดูไฟล์:** กดการ์ดเพื่อดูภาพ/PDF/เสียง/วิดีโอในหน้า
  - "ตรวจความครบถ้วน" เทียบ SHA-256 กับตอนรับเข้า
  - ดาวน์โหลดต้องใส่เหตุผล
- **ทะเบียนของกลาง:** เพิ่มรายการ (ติ๊ก "ดิจิทัล" สำหรับโทรศัพท์/คอมพิวเตอร์) · แก้ไข/ย้ายที่เก็บ (ต้องมีเหตุผล) · ส่งมอบ/รับคืน
- **บันทึกการครอบครอง:** ทุกการรับ เปิด ดาวน์โหลด และส่งมอบ ว่าใคร เมื่อไร เพราะอะไร
- **เอกสาร:** ออก "บัญชีของกลาง" และ "บันทึกตรวจยึดพยานหลักฐานดิจิทัล" จากหน้าออกเอกสาร

### 9.13 เทมเพลตเอกสาร (หัวหน้า/ผู้ดูแล)
1. **เตรียมไฟล์:** เลือกเอกสาร → "ดาวน์โหลดไฟล์มาตรฐาน" ใช้เป็นต้นแบบ แล้วแก้ถ้อยคำใน Word
   - ช่องข้อมูลพิมพ์ในวงเล็บปีกกา เช่น `{คดี.เลขคดี}` `{ผู้กล่าวหา.ชื่อเต็ม}` `{พงส.ยศชื่อ}` (รายการชื่อช่องที่ใช้บ่อยอยู่ในภาคผนวก 13.3)
   - ตารางที่ต้องทำซ้ำต่อรายการ ให้ใส่ช่องแบบ `{ของกลาง.ชื่อ}` ในแถวเดียว ระบบทำซ้ำให้
2. **อัปโหลด** → ระบบสแกนช่อง → จับคู่ช่องที่ชื่อไม่ตรงกับข้อมูลในระบบ หรือเลือก "เว้นว่าง" ถ้าจะเขียนด้วยมือ → เลือกเลขไทย/อารบิก → เปิดใช้
3. **ทดลองเติมกับคดี** ก่อนใช้ได้ · ย้อนกลับเวอร์ชันหรือกลับไปใช้ไฟล์มาตรฐานได้ทุกเมื่อ
4. **เพิ่มเอกสารใหม่ของหน่วย:** ตั้งชื่อ เลือกกลุ่ม แล้วอัปโหลด เอกสารจะขึ้นในหน้าออกเอกสารทันที

### 9.16 แจ้งเตือน โอนคดี และลิงก์ติดตามของผู้แจ้ง
- **กระดิ่ง:** ระบบตรวจทุกชั่วโมง แล้วแจ้งเจ้าของคดีเมื่อกำหนดเวลาเหลือ 3 วัน · 1 วัน · ครบวันนี้ · เลยกำหนด
  - แต่ละขั้นแจ้งครั้งเดียว
  - แจ้งเมื่อพบตัวระบุซ้ำข้ามคดี และเมื่อคดีถูกโอนด้วย
- **โอนคดี (หัวหน้า):** หัวคดี → "โอนคดี" → เลือกพนักงานสอบสวนในกลุ่มงาน → ใส่เหตุผล
  - เจ้าของเดิมและเจ้าของใหม่ได้รับแจ้ง
  - ลงบันทึกพนักงานสอบสวนอัตโนมัติ
- **ลิงก์ติดตามสำหรับผู้แจ้ง:** การ์ด "หน้าติดตามสถานะสำหรับผู้แจ้ง" ท้ายหน้าคดี
  1. สร้างลิงก์ (อายุ 30 วัน ถึง 1 ปี) → ให้ผู้แจ้งสแกน QR หรือส่งลิงก์
  2. **"แจ้งความคืบหน้าให้ผู้แจ้ง":** พิมพ์ข้อความแล้วกด "เผยแพร่"
     - ข้อความไปขึ้นในหน้าติดตาม และเก็บในบันทึกพนักงานสอบสวน
     - รายการอื่นในบันทึกพนักงานสอบสวนกด "ให้ผู้แจ้งเห็น" ได้เช่นกัน
  3. ผู้แจ้งเห็นเฉพาะสถานะและข้อความที่เผยแพร่ ไม่เห็นข้อมูลอื่นของคดี
  4. สร้างลิงก์ใหม่ = ลิงก์เดิมใช้ไม่ได้ · กด "ยกเลิกลิงก์" ได้ทุกเมื่อ
  - ผู้แจ้งจะเปิดลิงก์จากนอกหน่วยได้ เมื่อหน่วยแยกหน้าสาธารณะไว้ใน DMZ แล้วเท่านั้น (หัวข้อ 11)

## 10. การดูแลระบบ: สำรอง กู้คืน อัปเดต

คำสั่งในหัวข้อนี้รันในโฟลเดอร์ `ccid4`
- แบบเครื่องเดียว: เติม `-f docker-compose.local.yml` หลัง `docker compose` ทุกคำสั่ง
- แบบเซิร์ฟเวอร์: `make` มีทางลัดบางคำสั่ง ดู `Makefile`

### 10.1 เปิด/ปิด/ดูสถานะ

หยุดระบบ (ข้อมูลยังอยู่):

```bash
docker compose stop
```

เปิดระบบ:

```bash
docker compose up -d
```

ดูสถานะทุกส่วน:

```bash
docker compose ps
```

ดูบันทึกการทำงานของเว็บและงานเบื้องหลัง:

```bash
docker compose logs -f web worker
```

### 10.2 สำรองข้อมูล (ควรทำทุกวัน)

ต้องสำรองทั้ง **ฐานข้อมูล** และ **ไฟล์** (เอกสาร เสียง พยานหลักฐาน) เก็บไว้นอกเครื่อง เช่น NAS ของหน่วยหรือดิสก์ที่เข้ารหัส

สำรองฐานข้อมูล:

```bash
docker compose exec -T db pg_dump -U ccid4 -Fc ccid4 > ccid4-db-$(date +%F).dump
```

สำรองไฟล์ทั้งหมด:

```bash
docker compose exec -T web tar czf - -C /data media > ccid4-files-$(date +%F).tgz
```

ตั้งให้ทำอัตโนมัติทุกคืนบน Linux: เพิ่ม 2 คำสั่งข้างบนใน `crontab -e` (ใส่ `cd /ที่อยู่/smart-ccid4/ccid4 &&` นำหน้า และ `%` ต้องเขียนเป็น `\%`) แล้วย้ายไฟล์ไปที่เก็บสำรอง

### 10.3 กู้คืน

กู้คืนบนระบบที่ติดตั้งใหม่และยังไม่มีข้อมูล (ไฟล์พยานหลักฐานเป็นแบบอ่านอย่างเดียว เขียนทับไฟล์เดิมไม่ได้)

กู้คืนฐานข้อมูล:

```bash
docker compose exec -T db pg_restore -U ccid4 -d ccid4 --clean --if-exists < ccid4-db-YYYY-MM-DD.dump
```

กู้คืนไฟล์:

```bash
docker compose exec -T web tar xzf - -C /data < ccid4-files-YYYY-MM-DD.tgz
```

หลังกู้คืนให้เปิดหน้าพยานหลักฐานของคดีสำคัญ แล้วกด "ตรวจความครบถ้วน" เพื่อยืนยันว่าไฟล์ครบและไม่ถูกแก้

### 10.4 อัปเดตเป็นเวอร์ชันใหม่

1. สำรองข้อมูลก่อน (10.2)
2. ดึงโค้ดใหม่:

   ```bash
   git pull
   ```

   หรือดาวน์โหลด ZIP ใหม่ แล้วคัดลอกไฟล์ `.env` เดิมไปไว้ในโฟลเดอร์ใหม่
3. สร้างใหม่และเปิดระบบ:

   ```bash
   docker compose up -d --build
   ```

   ระบบ migrate ฐานข้อมูลให้เองตอนเปิด
4. แบบเครื่องเดียวรันตัวติดตั้งซ้ำแทนได้ ข้อมูลไม่หาย

### 10.5 ข้อควรระวัง
- **ห้ามเปลี่ยน `DJANGO_SECRET_KEY` หลังใช้งานแล้ว** ถ้าจำเป็นต้องเปลี่ยน ให้สร้างดัชนีเชื่อมคดีใหม่ทันที:

  ```bash
  docker compose exec web python manage.py reindex_identifiers
  ```
- อย่ารัน `docker compose down -v` บนระบบจริง คำสั่งนี้ลบฐานข้อมูลและไฟล์ทั้งหมด
- ดิสก์ใกล้เต็มทำให้รับไฟล์และอัดเสียงไม่ได้ ตรวจพื้นที่ด้วย `df -h` อย่างน้อยสัปดาห์ละครั้ง

## 11. ความปลอดภัยและ PDPA

- **ที่เก็บข้อมูล:** ข้อมูลจริงอยู่ในเครื่องหรือเซิร์ฟเวอร์ของหน่วยเท่านั้น
  - เซิร์ฟเวอร์อยู่ในห้องที่ควบคุมการเข้าออก
  - เข้ารหัสดิสก์ (LUKS / BitLocker / FileVault)
- **การเข้าถึง:** เปิดให้เข้าได้เฉพาะวงแลนของหน่วย ไม่เปิดพอร์ตออกอินเทอร์เน็ต
  - ถ้าต้องให้ประชาชนแจ้งความออนไลน์ ต้องให้ฝ่ายเทคนิคแยกหน้าสาธารณะไว้ในโซนแยก (DMZ) ก่อน
- **บัญชีผู้ใช้:** หนึ่งคนหนึ่งบัญชี ห้ามใช้ร่วม
  - ตั้งวันหมดอายุให้ผู้ช่วยหรือผู้ฝึกงาน
  - ปิดบัญชีทันทีเมื่อย้ายหน่วย
- **ก่อนบันทึกเสียงหรือเก็บข้อมูล:** แจ้งผู้ให้ถ้อยคำทุกครั้ง
- **ข้อมูลอ่อนไหว:** เลขบัตรและเลขบัญชีแสดงแบบปิดบังเป็นค่าเริ่มต้น การดูเต็ม ดาวน์โหลด และส่งออก ถูกบันทึกทุกครั้ง
- **ประวัติการใช้งาน:** หัวหน้าตรวจที่ `/audit/` เป็นประจำ
- **ไฟล์ `.env`:** มีรหัสลับ ห้ามส่งต่อ ห้ามใส่ใน Git และห้ามถ่ายภาพหน้าจอ
- **ไม่ใช้บริการภายนอก:** ระบบไม่ใช้ CDN ไม่ใช้ AI ภายนอก และไม่เรียก blockchain explorer · ทุกฟีเจอร์ที่ส่งข้อมูลออกนอกเครือข่ายปิดไว้เป็นค่าเริ่มต้น
